## 一、会议背景

用户看过 A–H 八稿静态稿后的核心反馈原话（开题材料记录）：

> **「A~H 八稿皆嫌不美观」**

开题诊断指出其最大共同因子：**14px 圆角 + 1px 边框 + 16px 内边距的同构白盒**与 14~16px 等距 gap 在全页重复 10+ 次（variant-h.html:88,101,112,116），留白无大小分级、视觉重量均质——「卡片墙」是八稿共有气质。

本次会议目标：

1. 以信息架构与真实数据最完整的方案 H 为基准做开题诊断（痛点 / 议程 / 保留优点）；
2. UI / UX / 产品三方两轮评审，对八项议程逐项定调；
3. 产出三套气质拉开、可直接落地的的新方案 I / J / K，并完成静态稿质检。

### 2.2 议程（8 项）

1. 总览页信息架构重排：如何建立「结论层 / 趋势层 / 明细层」的明确视觉分区与阅读动线，56 组规格表是否让出首屏、图表是否升格为页面主视觉（UI+产品共同定调）
2. 导航架构收敛：页签与侧栏功能重复、页面名三处同显是否合并或差异化分工；侧栏 5 个菜单项的宽度 / 存在性价比（UX 主导）
3. 数字层级与 KPI 形态：四等分卡是否改为「一条状态栏 / 超大 hero + 次级指标」，800.84 万的字号与占比、A/B 果拆分是否降为次级、全站字号阶梯是否重排（UI 主导）
4. 卡片语言与间距节奏：是否整体替换为规则线分区 / 无卡片 / 混合密度，如何建立大中小三级留白节奏（UI 主导）
5. 表格排版降噪：三明治结构与多元素并存的减法；列表页合计行权重倒置修正；明细表折叠 / 收敛版式（UI+UX）
6. 筛选与动作的位置语义统一：筛选回归独立筛选条还是常驻侧栏；列表页筛选区缺位补位（UX+产品）
7. 色彩权重与整体气质定向：深色块与 4 个相近绿的收敛分层；顺仔渐变卡去营销化；基于 compass 六方向投票确定三套新方案各自气质（三方共评）
8. 容器规范与响应式底线：四种容器混排统一规范；保持 960px 单列降级与手机底部 tabbar；菜单命名与线上口径统一（UX+产品）

### 2.3 保留优点（5 条，新方案必须继承）

1. **真实数据内嵌的静态稿评审机制**：H 稿 DATA 直接来自 53000 实测（variant-h.html:637-638），评审所见即线上所得；新方案必须沿用真实口径数据（29,771 件 / ¥8,008,442.99 / 均价 269.00 / 15 单），防止设计与落地两张皮。
2. **图表与线上组件一一映射**：等级环 = GradePieChart、每日折线 = DailySalesTrendChart、市场环 / 品牌柱 = MarketSalesAnalysis、双轴图 = SettlementDailyPriceChart、七列表 = SettlementGradeBreakdown（variant-h.html:8-14 注释），换壳不换图表内核，落地成本低。
3. **等级色彩语义系统全链路一致**：GRADE_COLOR / GRADE_BG / GRADE_NAME 统一映射（:647-649），KPI、徽章、进度条、环图、对比图共用同一套 A/B/OTHER 颜色语言。
4. **五屏完整信息架构与页签式工作台**：总览 / 列表 / 详情 / 对比 / 录单链路齐全；线上 AppShell.vue:709-739 页签栏已具备右键菜单、关闭其他、刷新等成熟交互。
5. **全局 tabular-nums 数字排版与成体系的移动端降级**：960px 单列断点（:268-271）、手机模式 + 底部 tabbar（:244-266），对应线上 mobile-tabbar 与更多面板（AppShell.vue:813-830）。

## 三、三方意见要点

### 3.1 首轮

#### UI 视觉设计师

**方向偏好**：① 规则线报告版（放弃白卡墙，细分隔线 + 分级留白，KPI 无盒超大数字行，深色一页只出现一次，瑞士极简 × 晨报）；② 深色报告头 + 全白正文（唯一满宽深色报告头承载口径 + 超大 800.84 万 + 结论句）；③ 图表主视觉版（每日折线升 260px+ 首屏主角，56 组表让出首屏改收敛表，按结论→趋势→明细三级递降密度）；④ 台账密表版（全细线、无底色行、徽章改 6px 色点、tabular 右对齐、近乎无圆角无阴影）。

**发现要点（9 条）**：

- **字号阶梯**：px 与 rem 混写，11~15px 区间共存 15 个声明值；页面标题 20px 反而小于 KPI 数字 24px，「页 > 区 > 数据」关系读不出 → 压缩为 6 档离散阶梯（正文 13 / 辅助 12 / 微标 11 / 区块标题 15 / 页面标题 24 / KPI 主数字 32~40），统一一种单位书写。
- **KPI 四卡**：hero 只换深底不换尺寸，首屏没有唯一焦点 → hero 出卡：总销售额直接坐页面底色上 40px 无盒无描边，A/B 拆分改 10px 双色堆叠占比条 + 图例数字。
- **绿色系统与深色块**：4 个近似绿并存（--brand #2f7a4f / --primary #2f7d57 / gA #16856b / 渐变 #3d8a5d），深色块散布五个不同高度 → 绿收敛两支硬分工（品牌绿管交互、A 果绿管数据），立「深色一页一次」规则。
- **规格七列表**：「深-浅-深」三明治 + 行内五处强调并存 + 占比文字与迷你条重复编码（:159-160,:931-932）→ 表头浅底灰字，每行只留总件数与均价两个强调位，徽章改 6px 色点，回到「细线 + 数字」台账语言。
- **列表页合计行**：全表最重的颜色给了汇总行，双重倒置 → 合计移表尾去底色，仅靠字重与上线；「汇总的墨色可以重，底色不能重」。
- **容器体系**：三档圆角（12/14/8px）+ 五层背景嵌套 + grid2 底边不齐 → 圆角收敛两档（容器 12 / 控件 6），行级信息改裸行，双卡 align-items:stretch + 44px 基线网格。
- **图表高度**：六处 150~200px 随手值；市场环与品牌柱各只有两个值却各占整卡，信息量最大的 15 点折线反被压扁 → 「同组同高」，序列型给高度、低基数给一行字。
- **顺仔结论条**：全页唯一斜渐变容器，营销浮层语言与工具气质冲突 → 去渐变去头像去底色，改「左 3px 品牌绿竖线 + 正文」引言式结论块。
- **pagehead 口径重复**：说明与 hero 副行双处维护，筛选与动作同排同款式 → 口径只在 hero 出现一次；条件与动作以控件语言区分、左右分组。

#### UX 交互设计师

**方向偏好**：① 砍掉 232px 常驻侧栏做「顶栏内嵌主导航 + 页签栏只管已打开页面」两层骨架，命名统一回线上大白话口径；② 总览改「结论层（hero + 顺仔合并首屏）→ 趋势层（240px+ 四图主视觉）→ 明细层（规格表默认折叠到小计）」三段式；③ 三套共享一张跨方案表格规范（浅表头 + 白底行 + 合计移表尾 + 徽章降色点 + 进度条与占比文字二选一）；④ 双端分工：桌面保垂直预算、移动端坚持「三主入口 + 更多」tabbar、详情做列表下钻页。

**发现要点（10 条）**：

- **三层导航**：页签与侧栏共用同一 show()、页面名三处同显、静态稿命名与线上口径（AppShell.vue:111-119）不一致 → 砍掉一层，5 个页面的产品不需要三层导航；至少一套做无侧栏对照。
- **阅读动线错位**：用户决策链是「赚了多少 → 走势如何 → 哪个规格贡献大 → 有没有异常 → 要不要下钻」，实际顺序把 56 组明细插在两层图表之间、顺仔解读沉到第 5 屏 → 重排三段式 + 段落级间距分级 + 段标眉标扫读锚点。
- **KPI 混排**：总量与拆分同级、总量补充信息反被降级 → hero 层超大数字 + 拆分层；等级拆分与等级环图例信息高度重叠，可合并省掉一个区块。
- **视觉预算倒挂**：应该当主角的趋势图做成缩略图、应该收敛的明细无限铺 → 「图表升格」与「表格降级」要作为一对决策同时落。
- **筛选与动作**：总览筛选做成按钮与动作同款式同排；列表页筛选完全缺位 → 全站统一两套位置语言：筛选 = 标题下独立表单条，动作 = 页头右侧按钮组（主按钮唯一）。
- **表格行身份**：三种行身份主要靠背景色深浅区分，扫读需先辨色再读数 → 三级行身份改「缩进 + 字重 + 线条」而非颜色深浅。
- **两页合计样式不一致**：列表页绿底合计与规格表深绿合计是同一种「合计 > 明细」权重错配 → 立全站组件规范：数据行永远比合计行视觉重，作为三套共享不变规范。
- **容器收敛**：读者要学习四种「盒子」的语义才能读完一页 → 容器收敛为两类：区块容器与键值行；圆角 / 内边距 / 边框全站只允许一组值。
- **录单页重复入口**：tiles 与功能卡同样两件事铺两次，且与线上「录单 / 导入直接进上传页」的交互模型相悖 → 删 tiles，上传为默认态、手工录单为次级。
- **移动端**：静态稿把「详情」提为一级 tab 与线上模式不符；手机 KPI 2×2 无层级 → tabbar 对齐「三主入口 + 更多」；详情为下钻页；手机 KPI hero 独占一行 + 次级两列小卡。

#### 产品经理

**方向偏好**：① 必须有一套「账单流水心智」（微信账单 / 银行流水）：总览 = 月度账单、详情 = 单笔竖式收支单（到手金额最大）、金额以元为主、万元辅助；② 必须有一套「台账 / 报表心智」：结论即表格、全边框线、合计在底部、可直接打印对账——「不美观的解法是秩序而不是装饰」；③ 必须有一套「掌柜金融 App 心智」：hero 只放总销售额、A/B 果金额对照卡、单层大白话菜单；④ 共同产品底线：**每屏首屏 200px 内直接回答本轮三问（这一柜怎么样 / 哪个等级赚钱 / 下一柜怎么装）**，结论层永远在最上、56 组明细永远下沉可展开、列表页必须有金额与均价列。

**发现要点（10 条）**：

- **三问答案埋没**：答案全部在第 6 块顺仔纯文字里，首屏只有四个孤立数字 → KPI 与图表之间插入「结论层」：一句大字结论 + 2~3 条带数字要点，压到 60-80px。
- **等级金额要心算**：A/B 果卡主数字是件数，金额要用户自己算（A 果约 546.9 万、B 果约 253.9 万恰为 800.8 万主体但页面上没有）→ 改两级结构，A/B 果以金额为主数字。
- **规格表无排序信息**：最大规格与 1 件碎规格同级陈列 → 总览只放 Top 10 紧凑榜，其余折叠或独立子页。
- **详情页第一问错位**：facts 四小卡全是物流字段没有一个金额，第一个钱数在页面中部 13px 小字 → 详情首屏做竖式流水（销售 → 售后 → 货款 → 费用 → 应付，应付金额最大字号）。
- **列表缺金额均价列**：贸易商无法在列表层回答「哪一柜卖得最好 / 均价最高」→ 补销售额、加权均价两列 + 列头排序 + 表单式筛选条。
- **金额单位混乱**：总览万元、结算口径元、规格表纯数字，核账需来回换算；OTHER 9.05 / 0.00 元均价行无注释 → 全站统一单位策略；OTHER 零价行显示「不计价」。
- **导航命名倒退**：线上大白话三主入口 + 更多，静态稿用回五个术语项，移动端 tabbar 放了无法直达的「详情」→ 回归单层导航 + 线上命名；详情只从列表 / 总览点进。
- **条件与动作不分**：用户分不清哪些是筛选哪些是操作，不知道改条件后数字会不会自动变 → 全站统一表单式筛选条（含「筛选」主按钮明确语义）。
- **录单页品种命名冲突**：「品种」下拉 A/B/C/D/E/F 与全站等级语义正面冲突 → 展示真实品种字典或标签改「品种代码」并做视觉区隔。
- **（附带）静态稿信息架构与线上真实交互模型相悖**：录单入口重复 + 表单过窄。

### 3.2 二轮交锋

#### UI 视觉设计师（反驳与新增）

- **反驳 UX「四图等权升格」**：市场环只有 12:3 两扇区、品牌柱只有 14:1 两根柱，给两个数字各配 300px 整卡是把信息密度最低的图提到与 15 点折线同等地位，总览会变成图表展览 → 图组改「一主两副」：每日折线 260~280px 独享主视觉，等级环降 4 列副图同排，市场 / 品牌彻底去图位改 12px 分布条文本。
- **反驳 PM「全站以元为主数字」**：hero 主数字用元是 13 个字符，48px 下宽约 450~500px 吃尽首屏横向空间，千万位级数字人眼需逐位核对 → **金额排版双轨制**：hero / 对比页「万元大字 + ¥ 元级小字辅助行」；对账场景（详情流水、规格表、列表金额列、导出）一律「¥ + 元 + 千分位 tabular-nums」。OTHER「不计价」采纳。
- **修订 PM「A/B 金额对照卡」**：会在已判「四等分卡是卡片墙根源」的位置再起两张同构白卡，且拆分与等级环图例高度重复（金额已复核：18,907×289.28≈¥5,469,417、10,819×234.64≈¥2,538,570，与总额差约 460 元）→ 不新起卡，环图图例每行扩为「色点 + A 果 · 18,907 件 · 63.5% · ¥546.9 万 · 均 289.28」，KPI 卡总数 4 → 0。
- **新增（两位均遗漏）**：品牌对比页 1fr:auto:1fr 对称双卡 + 居中「VS」对 14:1 一边倒的数据说谎，同一组数字三处重复 → 改「基准 + 差异」不等分版式，重复数字只留一处。
- **新增 · 表格行语言**：spec 表（斑马纹 + hover #eef6f0 + 行距 7px）与 plain 表（无斑马纹 + hover #f8fbf9 + 行距 10px）两套行语言割裂，62 行长表无 sticky 表头 → 跨方案表格规范补四条：全站一种行语言（无斑马纹 + 1px 行线 + 统一 hover）、行高 40px 基线、长表 thead + 首列双 sticky、数字列右对齐 tabular。
- **新增 · 小字号 800 合成粗**：grep 实测五处 13px 级元素 font-weight:800，中文系统字体无 800 字重，合成加粗笔画发糊双影，正是「不精致」观感直接来源 → 字重收敛四档（400/500/600/650），11~13px 禁 700 以上。
- **新增 · 中屏断点缺失**：全稿仅 960 一档断点，1366×768 常见设备无验证 → 新骨架至少三档成稿验收（≥1440 / 1280~1440 / <960 + 手机 tabbar）。
- **规格表收敛融合修订**：UX「默认小计」与 PM「Top10 榜」都做会出现两张同源数据的表 → 「一张表两种读法」：默认 6 组品牌×等级小计 +「展开全部 56 组」，展开态默认按件数降序即 Top 榜。
- **新增 · 红色双值**：--accent #9b3029 与 #e05a4e 两个红都承担「警示」→ 收敛为一支并限定语义（只出现在警示与负向）；交付一张色板表全站对号入座。

#### UX 交互设计师（反驳与新增）

- **反驳 UI「描边胶囊 vs 实底按钮」**：现状恰恰已是描边 / 实底并存，样式微调回答不了用户真正的疑问（点筛选会不会直接改数据）→ **位置语义为主、样式为辅**：筛选固定为标题下独立表单条（含「筛选 / 清空」明确语义），动作固定页头右上 + 分隔线。
- **反驳 PM「全站以元为主」**：总览 hero 的 ¥8,008,442.99 作主数字扫读效率反而低于 800.84 万；账单流水心智的正确适用域是详情页（那里有真实减项链），总览硬套「月度账单结余」是错误类比 → 按金额位数定单位规则：≥7 位万元主 + 元辅，≤6 位元主千分位；账单版式只用于详情页。
- **深色报告头的双端条件**：若报告头 100px+ 深色带不降级，移动端「首屏 200px 答三问」底线直接被吃掉 → 深色报告头必须同时交付移动端降级形态（浅色化保留版式或压 64px 单行摘要），每套骨架附手机首屏截图验证。
- **修订 PM「A/B 金额主数字」并补落地依赖**：方向正确，但 DATA.ovSpec.subs 每项只有 brand/grade/qty/price 四字段，页面现有数据画不出等级金额 → 采纳设计，落地清单必须列接口口径变更：后端 overview/grade-breakdown 补等级销售额字段 + 同步 frontend/src/api/types.ts + 记 docs/DECISIONS.md；静态稿先以真实推算值画出并标注「待接口字段」。
- **修订 UI「低基数图并入表头侧注」**：市场×品牌分布对贸易商有独立决策价值，完全藏进侧注会丢掉「往哪个市场发柜」维度 → 降级但不隐形：合并为趋势层末一行 12px 分布条，保留可展开 3 行真值。
- **新增 · 详情页返回路径缺失**：全页无返回列表入口，移动端页签隐藏后从属页无返回路径违反基础可达性 → pagehead 补面包屑或返回箭头，移动端顶栏返回箭头 + 页面名。
- **新增 · 「发起对比」无选择机制**：按钮承诺了页面上不存在的选择交互 → 二选一闭环：a) 行首 checkbox + 「对比（已选 n/6）」计数；b) 删列表页入口统一从详情页累加；至少一套完整画出勾选态。
- **新增 · 摘要表与列表页同构**：总览摘要只是列表缩水版，未提供新决策价值 → 改「Top 柜 + 最新柜」或「偏离大盘的柜」视角，行可点击下钻，每层各有信息增量。
- **新增 · 静态稿可达性回退**：线上有 aria-current / role=tablist / skip-link / focus-visible，静态稿全部丢失 → 三套新稿统一补回，落地清单把「可达性不低于线上现状」列为验收项。

#### 产品经理（反驳与新增）

- **骨架不再作为差异化变量**：采纳 UX 无侧栏方案为**共同骨架**——顶栏内嵌大白话导航（卖得怎么样 / 每一单 / 品牌对比 / 录单）+ 页签条只管已打开页面；首轮「至少一套单层导航」收紧为「三套统一无侧栏」。
- **反驳 UI「双色条」与 UX「图例合并」**：两个方案都把等级拆分压成件数占比口径，「哪个等级赚钱」会退回不可一眼答 → 修订为：A/B 拆分**必须保留金额为主数字**，形态可采堆叠条或图例合并，但旁边必须跟「A 果 ¥546.9 万 · 18,907 件 · 63.5% · 均 289.28」同级数字行；占比只作最次级信息。
- **反驳 UI「结论条压到区块标题等高」**：顺仔文字是三问答案的唯一自然语言载体，压到引文式小字等于删掉结论层；去营销化不等于降权 → 结论层保留 80~120px：hero 大金额 + 一句大字结论 + 2~3 条带数字要点；顺仔头像降为 14px 行内小图标。
- **反驳 UI「纯柜数分布条」**：纯柜数对「下一柜发哪个市场」没有决策价值，缺的是市场×均价 / 金额口径 → 降为 hero 次级行一行文字，腾出的版面给列表页做市场分组小计（市场×柜数×件数×加权均价）。
- **新增 · 对比入口语义分裂**：列表「发起对比」、详情「加入对比」、侧栏「品牌对比」三个入口互不交代去向，而品牌对比页口径是「品牌间最多 6 个」不支持柜间对比 → 统一对比心智：「与上一柜对比」直达两栏对照页或多选计数「加入对比 (2/6)」+ 悬浮已选清单；品牌对比页更名「品牌汇总」。
- **新增 · 详情页数字基准体系**：全页仅一处比较，287.87 是好是坏无从判断；方案 E 验证过「每个数字自带基准」方向（index.html:84），H 把它丢了 → 关键数字统一带「vs 上一柜 ±x% · vs 本期大盘 y」，首柜显示「首柜无基准」。
- **新增 · 打印对账场景**：深墨绿表头黑白打印后是实心黑块不可读、彩打耗墨——表头浅底不止是视觉减法，是**对账可用性**问题 → 「黑白打印可读」升格为三套共同硬约束。
- **新增 · 录单回执感**：单柜记录量几十行级别，录 52 行过程中没有实时小结与可撤销列表 → 表单下常驻「已录 n 行 · 合计件数 · 合计金额」+ 最近 3 行可撤销行卡。
- **新增 · 摘要表改 Top5 排行**：按销售额排序，列 = 商号 / 品牌 / 件数 / 销售额 / 均价，首行「销冠」标记直链详情，与列表页形成「总览看结论、列表查明细」分工。

### 3.3 会议收敛的关键共识

1. **共同骨架**：三套统一无侧栏——顶栏大白话导航（对齐 AppShell.vue:111-115）+ 页签条（保留线上成熟交互）；移动端「三主入口 + 更多」tabbar、详情为下钻页带返回。
2. **总览三段式**：结论层（hero 金额 + 结论条合并首屏，200px 内答三问）→ 趋势层（折线主视觉 + 等级环副图，低基数图降分布条）→ 明细层（规格表默认小计 + 可展开）。
3. **共享表格规范**：浅表头 + 白底数据行 + 合计移表尾仅字重与双线强调、徽章降色点、进度条与占比文字二选一、全站一种行语言、长表 sticky。
4. **金额双轨制**：≥7 位万元主 + 元级辅助（hero / 对比页）；对账场景一律 ¥ + 元 + 千分位 tabular-nums；OTHER 零价行显示「不计价」。
5. **色彩纪律**：品牌绿只管交互、A 果绿只管数据、警示红收敛一支；深色一页一次；字重四档、11~13px 禁 700 以上。
6. **落地依赖显性化**：A/B 等级销售额为推算值，需后端补字段 + 同步 types.ts + 记 DECISIONS.md；市场×均价口径后端暂无，静态稿以真实分布占位 + 口径注解。

## 四、三套方案定案

### 4.1 方案 I · 掌柜账单（variant-i.html）

- **定位**：微信账单 / 手机银行心智的「大数字少层级」账单版：**唯一深色报告头一屏给结论，其余全白细线**，服务不常上网的果农。
- **核心形态**：56px 白底单层顶栏（logo + 四项大白话导航），无侧栏无页签；总览满宽深墨绿报告头（桌面约 170px）——口径小字 + 800.84 万 48px 大字 + 同基线辅助行 + 结论句与带数字要点 + 市场 / 品牌分布行，深色全页仅此一处；A/B 果金额对照行（¥546.9 万 / ¥253.9 万 + 双色堆叠占比条，标注「待接口字段」）；详情页竖式收支单（应付金额最大字号）；录单删 tiles、带实时小结与撤销回执。
- **差异**：与 H——三层导航变单层直切、KPI 四等分卡变深色报告头 + 金额对照行、顺仔渐变浮层变报告头结论行、三明治表格变共享表格规范、摘要表变 Top5 排行、列表页补表单筛选条与金额 / 均价列；与 A/C/D——I 有唯一深色报告头、账单抬头语言与竖式收支单身份；与 B/E——无右侧常驻面板、无终端条，深色只出现一次。
- **适合人群**：不常上网的果农优先；重度多页签用户可能不适应（建议在 J/K 中选）。
- **风险**：① 深色报告头手机端必须降级（浅色化保留版式或压 64px 单行摘要），静态稿需交桌面 + 手机首屏截图验证；若嫌深色过重，可整体浅色化保留版式作退路。② A/B 果金额为推算值，落地依赖后端 overview/grade-breakdown 补字段 + 同步 frontend/src/api/types.ts + 记 docs/DECISIONS.md。③ 砍页签与线上成熟页签交互冲突，落地前需确认多单比对工作流不受损。

### 4.2 方案 J · 打印台账（variant-j.html）

- **定位**：纸质台账 / Excel 心智的全边框密表版：**结论即表格、黑白打印可对账**，信息密度与核账信任最大化，专业高效——PM 定调「不美观的解法是秩序而不是装饰」。
- **核心形态**：44px 白底细线顶栏 + 36px 页签条两层；报表头（1px 边框 + 左 4px 墨色实条 + 打印按钮）；全站 1px 全边框线网格、零圆角零阴影零底色行，行高 32px 全站密度最高；图表全部装进全边框容器 + 浅灰 caption 条（图即表，140px 灰度友好）；@media print 隐藏导航 / 筛选、表格全边框、规格表自动展开 56 组、A4 纵向；金额一律 ¥ + 元 + 千分位；柜列表带市场分组小计（海吉星 12 柜 × 件数 × 均价 / 江南 3 柜 × …）。
- **差异**：与 H——容器语言从 14px 圆角白卡墙整体换成全边框线网格、三明治表格换浅灰表头 + 白底双线合计（黑白打印可读）、三层导航换两层、行高收到 32px、新增打印样式；与 D（同为高密度灰白）——D 仍是圆角卡片 + KPI 状态栏的现代压缩，J 是全边框表格化 + 报表头 + 打印优先，且补齐金额 / 均价列与市场分组小计；与 F/G/H——全部无侧栏；与 E——无终端条与深色报告头，基准改为表格列。
- **适合人群**：信任纸质台账的老一辈、需要打印对账的贸易商；纯看板偏好者不适。
- **风险**：① 32px 行高 + 11.5px 表格字对视力弱 / 触屏用户偏紧——手机端行高回落 40px（密度只在桌面保满）。② 「结论即表格」削弱一眼看趋势能力，J 与 K 是密度光谱两端，选型需用户明确拍板。③ 打印样式静态稿只能附一页 print 模拟，真实效果需落地后验证。④ 市场×均价口径后端暂无，小计均价列以真实分布占位 + 口径注解。

### 4.3 方案 K · 图表报告（variant-k.html）

- **定位**：瑞士规则线 × 现代 BI 的图表主视觉报告版：**三段式信息架构（结论→走势→明细）、无卡墙细分隔线分区、每个关键数字自带基准**，专业分析高效。
- **核心形态**：56px 白底顶栏（logo 区下沿 2.5px 墨色粗规则线贯穿全宽——深色一页一次的形态是「线」不是「块」）+ 36px 页签条；白底瑞士报告头 + 独立筛选表单条；12 列网格三段式：结论层（无盒 hero 40px + 结论条 80~120px + A/B 拆分行）→ 趋势层（每日折线 260~280px 唯一主视觉 + 等级环 4 列副图 + 分布条收尾）→ 明细层（规格表 + 柜 Top5）；段间 32 / 段内 12 / 相关组 8px 三档间距 + 11px 字距加宽段标眉标；全站圆角仅控件 6px、无阴影无渐变；**基准体系**——关键数字带「vs 上一柜 ±x% · vs 本期大盘」、折线带「平时水平」均线、首柜显示「首柜无基准」；列表页行首 checkbox 勾选对比「（已选 n/6）」；响应式三档（≥1440 / 1280~1440 / <960 + 手机 tabbar）；补回 aria-current、focus-visible、sticky 表头等可达性。
- **差异**：与 H——三层导航换顶栏 + 页签 + 瑞士报告头、四等分卡换无盒 hero + 拆分行、卡片墙换细分隔线分区、图表从缩略图升主视觉一主两副编排、新增基准体系 / 勾选对比 / 中屏断点；与 A——有 12 列三段式 + 强基准 + 批量勾选；与 B——无右侧常驻面板；与 E（最近亲）——K 全白底 + 墨色规则线（深色块为零），基准扩展到每个关键数字；与 F/G/H——全部无侧栏。
- **适合人群**：贸易商、重度分析与年轻用户；不常上网的果农建议优先 I。
- **风险**：① 「无卡片」若段标字距与三档间距执行不到位，易退化成「什么都没有」的寡淡——段标与间距分档是硬执行点。② 折线 260~280px + 三段式使总览纵向变长，Top5 与规格表必须守住默认小计态。③ 基准体系有数据依赖：「vs 上一柜」需相邻柜口径、「平时水平」均线需前端口径定义、A/B 等级销售额需后端补字段 + 同步 types.ts + 记 DECISIONS.md。④ 「勾选对比 (n/6)」与详情页「与上一柜对比」并存时对比入口仍有两个，落地前需用户拍板主路径。

### 4.4 三套共享的落地规范（会议不变项）

- 共同骨架：无侧栏顶栏导航 + 页签条；移动端「三主入口 + 更多」tabbar、详情下钻带返回。
- 共享表格规范：浅表头 + 白底数据行 + 合计移表尾白底双线、徽章降色点、进度条与占比二选一、一种行语言、长表 thead sticky、数字列右对齐 tabular-nums。
- 字号 6 档阶梯与字重 4 档；金额双轨制；OTHER 零价行「不计价」。
- 列表页补销售额 / 加权均价列；品牌对比页更名「品牌汇总」；录单页删 tiles、品种控件与等级语义区隔。
- 黑白打印可读、可达性不低于线上现状，列为验收项。
