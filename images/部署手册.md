# SLD 水果市场销售分析系统 — 用户端 Docker 生产部署手册

> 适用版本：`fruits_ana`
> 文档位置：`fruits_ana/images/部署手册.md`
> 日期：2026-09-22

## 1. 部署包说明

本部署包面向“生产服务器已安装 Docker，MySQL 已单独部署”的场景。上传包内包含已经构建好的
用户端镜像文件，生产服务器不需要拉取镜像，也不需要在服务器上重新构建前端或后端代码。

解压后的目录结构：

```text
fruits_ana/
└── images/
    ├── fruits-ana-backend.tar
    ├── fruits-ana-web.tar
    ├── config/
    │   ├── docker-compose.yml
    │   ├── .env.docker.example
    │   └── nginx/
    │       └── fruits_ana.conf
    ├── scripts/
    │   ├── check.sh
    │   ├── build-images.sh
    │   ├── load-images.sh
    │   ├── configure-env.sh
    │   ├── start.sh
    │   ├── stop.sh
    │   ├── status.sh
    │   └── package.sh
    └── 部署手册.md
```

## 2. 前置条件

- Linux 服务器，已安装 Docker Engine 和 Docker Compose v2。
- MySQL 已部署，可访问地址已确认。
- 已创建数据库和业务账号，例如数据库 `fruits_ana`。
- 端口 `53000`、`8000` 未被占用。
- 上传包已解压到 `/home/python/workspace/`，目录层级保持不变。

检查命令：

```bash
docker --version
docker compose version
./fruits_ana/images/scripts/check.sh
```

## 3. 构建镜像与打包

部署包可以随时重新生成。如果需要重新构建用户端 `backend`、`web` 镜像，并覆盖
`images/` 目录下的 `.tar` 文件，在仓库根目录执行：

```bash
cd /home/python/workspace/fruits_ana
./images/scripts/build-images.sh
```

镜像构建并导出完成后，生成部署压缩包：

```bash
cd /home/python/workspace/fruits_ana/images
./scripts/package.sh
```

生成文件位于 `/home/python/workspace/`：

```text
fruits_ana_deploy_YYYYMMDD_HHMMSS.tar.gz
```

> 部署包只包含 `config/.env.docker.example`，不包含 `config/.env.docker`；
> 该文件由现场的 `scripts/configure-env.sh` 生成，避免数据库口令 / API Key 被发到部署包。

下载示例：

```bash
scp /home/python/workspace/fruits_ana_deploy_*.tar.gz 用户@服务器:/tmp/
```

## 4. 初始化数据库

如果生产数据库尚未建库或建用户，请先执行（示例）：

```sql
CREATE DATABASE fruits_ana DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'fruits_user'@'localhost' IDENTIFIED BY '改成强密码';
GRANT ALL PRIVILEGES ON fruits_ana.* TO 'fruits_user'@'localhost';
FLUSH PRIVILEGES;
```

若需要迁移旧数据，请先导入数据库，再启动应用：

```bash
mysqldump --single-transaction --routines --triggers \
  --set-gtid-purged=OFF -h 旧库地址 -u 旧库用户 -p fruits_ana > fruits_ana.sql

mysql -h 127.0.0.1 -u fruits_user -p fruits_ana < fruits_ana.sql
```

## 5. 加载镜像

```bash
cd /home/python/workspace/fruits_ana/images
./scripts/load-images.sh
```

加载后确认两个用户端镜像存在：

```bash
docker images | grep -E 'fruits-ana-(backend|web)'
```

预期包含：

```text
fruits-ana-backend:local
fruits-ana-web:local
```

## 6. 配置环境变量

```bash
cd /home/python/workspace/fruits_ana/images
./scripts/configure-env.sh
```

该脚本会从 `config/.env.docker.example` 生成 `config/.env.docker`。请至少修改：

| 配置项 | 说明 |
| --- | --- |
| `FRUIT_ANALYSIS_DATABASE_URL` | 生产 MySQL 连接串，格式见 example |
| `FRUIT_ANALYSIS_AI_BASE_URL` | AI 服务地址；不需要 AI 可留空 |
| `FRUIT_ANALYSIS_AI_API_KEY` | AI API Key；不需要 AI 可留空 |
| `FRUIT_ANALYSIS_COOKIE_SECURE` | 使用 HTTPS 时改为 `true` |
| `FRUIT_ANALYSIS_SMTP_HOST` | SMTP 服务器地址，例如 `smtp.exmail.qq.com` |
| `FRUIT_ANALYSIS_SMTP_PORT` | SMTP SSL 端口，通常为 `465` |
| `FRUIT_ANALYSIS_SMTP_USER` | SMTP 登录账号，通常为发件邮箱 |
| `FRUIT_ANALYSIS_SMTP_PASSWORD` | SMTP 登录密码 / 授权码 |
| `FRUIT_ANALYSIS_SMTP_FROM` | 发件人地址，通常与 SMTP_USER 一致 |

未配置 SMTP 时，注册与忘记密码的验证码邮件无法发送。
注意：`.env.docker` 包含数据库口令、SMTP 密码和 API Key，不要提交到 Git 或发送到公共渠道。

## 7. 启动服务

```bash
cd /home/python/workspace/fruits_ana/images
./scripts/start.sh
```

脚本会显式加载 `config/docker-compose.yml`，Compose 项目名为 `fruits-ana-offline`，
只管理本目录对应的用户端容器。

启动顺序由 Compose 控制：

1. `fruits-backend` 健康检查通过。
2. 启动 `fruits-web`。

## 10. 版本更新

1. 上传新版本镜像 `.tar` 到用户端 `images` 目录。
2. 加载新镜像：

```bash
cd /home/python/workspace/fruits_ana/images
./scripts/load-images.sh
```

3. 重建并启动容器：

```bash
./scripts/stop.sh
./scripts/start.sh
```

4. 按第 8 节验证。若新版本异常，可用旧镜像重新导入后回退。

## 11. 数据与备份

- 上传原件与运行日志通过 bind mount 直接落在宿主机目录（相对于
  `config/docker-compose.yml`）：
  - `fruits_ana/images/config/data/uploads/` ← 容器 `/app/backend/data/uploads`（上传的 xlsx 原件）
  - `fruits_ana/images/config/data/logs/` ← 容器 `/app/backend/data/logs`（`fruits_ana.log` 及轮转备份）
- 容器以 root 运行，上述目录文件属主为 root，宿主机查看 / 备份需 `sudo`。
- 停止服务使用 `stop.sh`，不会影响这两个目录；清空数据需手动删除
  `config/data/`，操作前务必备份。
- 如需把数据放到别的位置（如独立数据盘），先设置环境变量再启动：

  ```bash
  export FRUITS_DATA_DIR=/opt/fruits_ana/data
  ./scripts/start.sh
  ```

  注意：`FRUITS_DATA_DIR` 只能通过 shell 环境变量传入；写进 `.env.docker` 无效
  （该文件只注入容器内部环境变量，不参与 compose 挂载路径解析）。
- 2026-09-30 之前的部署包用命名卷 `fruits-ana-offline_fruits_uploads` 保存上传原件，
  升级后如需找回卷内数据，在 `images/config/` 目录下执行：

  ```bash
  docker run --rm \
    -v fruits-ana-offline_fruits_uploads:/from \
    -v "$(pwd)/data/uploads":/to \
    alpine cp -a /from/. /to/
  ```

- 数据库备份建议使用 MySQL 定时任务独立执行：

```bash
mysqldump --single-transaction --routines --triggers \
  --set-gtid-purged=OFF -h 127.0.0.1 -u fruits_user -p fruits_ana \
  | gzip > fruits_ana_$(date +%Y%m%d_%H%M%S).sql.gz
```

## 12. 常见问题

### 端口被占用

先执行 `./scripts/check.sh`。如果端口被占用，请停止占用进程后再启动。

### 镜像不存在

确认镜像已加载：

```bash
docker images | grep -E 'fruits-ana-(backend|web)'
```

缺失时重新执行 `./scripts/load-images.sh`。

### 后端健康检查失败

查看后端日志：

```bash
docker compose -f /home/python/workspace/fruits_ana/images/config/docker-compose.yml logs fruits-backend
```

重点检查 `.env.docker` 中数据库连接串是否正确。
