## 四、基准提案（重点数据分级，供逐层讨论修正）

> 方法：先定每页「使用者的核心动作」，动作决定重点。分级：**P0 = 首屏必须一眼看到**，
> P1 = 次屏 / 可切换，P2 = 折叠 / 下钻。成本标注：已有 = 后端接口现成只是没展示；
> 小改 = 前端聚合或小后端改动；新增 = 需要开发。

### A. 销售总览 —— 老板动作：快速看行情 + 给等级 / 规格定价

**A-1 首屏大数带（P0）**（对应 gap review 改进 1）

| 指标 | 回答的问题 | 成本 |
| --- | --- | --- |
| 总柜数 | 生意规模 | 已有（现展示） |
| 销售金额 | 卖了多少钱 | 已有（现展示） |
| 总件数 | 卖了多少货 | 已有（total.sales_quantity 未展示） |
| **每件均价** | **现在行情多少钱（定价基准）** | 已有（total.weighted_avg_price 未展示） |
| A/B/C 等级均价胶囊（C 果含 BC） | 各等级行情，分级定价依据 | 已有（grades 未展示） |

**A-2 走势层（P0–P1）**（对应改进 2、5）

- 每日趋势指标集扩为 **金额 / 件数 / 均价 / 柜数** 四切（均价前端现算、柜数已有）——回答「行情涨还是跌」。
- 环比锚点：本旬 vs 上旬各等级均价涨跌箭头（小改：前端按 sale_date 分旬重算）。

**A-3 结构层（P1）**（对应改进 7、8、9）

- 市场分析补维度：柜数之外可切 **金额 / 件数 / 均价**（market_sales 后端已有，前端捡回）——哪个档口卖得贵、哪个走量不走价。
- 好果贡献：等级**件数占比 vs 金额占比**双条（grades 已有原料）——加价卖 A 果是否值得。
- 在售进度：Σ销量 ÷ 来货数量（小后端改动）——剩余库存压力决定定价松紧。

**A-4 规格层（P1–P2）**（对应改进 3、6）

- 规格价格展示形态二选一：现长表强化等级小计，或改「等级三列卡 + Top3 + 长尾折叠」（demo 已有原型）。
- 行情区间：期间最高 / 最低结算单均价（按商号聚合，原料已有）。

**A-5 告警（P2，定去留）**

- 经营异常（低均价单 / 等级占比偏离 / 日销量偏离）：后端在算、前端已下线——是否恢复、放哪。

### B. 结算单详情（查看明细）—— 动作：对账核对 + 回溯查数

**B-1 页头核对摘要带（P0，建议新增）**

| 指标 | 回答的问题 | 成本 |
| --- | --- | --- |
| **应付贵方总金额** | **这单最后结多少钱（最重要）** | 已有（computed_summary，现埋页底） |
| 货款合计 / 费用合计 | 应付构成 | 已有 |
| 总件数 vs 来货数量 | 超货 / 短货（现仅表脚小字警示） | 已有 |
| 每件均价 | 这单行情如何 | 小改（销售金额 ÷ 总件数前端现算） |
| 售后合计 | 售后影响 | 已有 |

**B-2 明细层（P1）**

- 销售明细按等级小结（件数 / 金额 / 均价），或等级小结胶囊。
- 结算核对表位置：随摘要带上移，或保留页底作底账（二选一）。

**B-3 页面分工（并入 D7）**

- 建议口径：「查看明细」= 单据核对（文件 vs 系统），「销售详情」= 单柜经营分析
  （等级 / 趋势 / 对比）。保持两页各司其职，还是合并入口，会上定。
