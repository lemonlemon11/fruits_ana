# 1. 文档说明

## 1.1 文档目的

本说明书描述 SLD-水果市场销售分析的现有功能、操作路径、业务规则和指标口径，帮助使用者快速理解系统能做什么、如何操作，并为验收和后续迭代提供统一依据。

## 1.2 目标读者

- 使用者：果农、业务人员、管理人员，用于日常查看销售数据。
- 验收人员：用于按功能点逐项核对系统是否满足需求。
- 开发与维护人员：用于理解功能边界、指标口径和页面交互。

## 1.3 术语说明

| 术语 | 含义 |
| --- | --- |
| 结算单 | 以商号为唯一业务键的一批销售数据；系统中通常对应一张导入的结算单文件或一张手工录单。 |
| 商号 | 我司商业合同唯一单据号，例如 637、624。展示时可能去除前缀「单」，但唯一键和接口参数仍使用原始商号。 |
| 单号 | 客户侧单据号，例如 宝贝-001；系统同时保留原始单号与适配后单号。 |
| 柜号 | 车柜标识，允许为空且可重复。 |
| 等级 | 统计等级统一为 A、B、C 三级；原始 BC 等级归入 C，AB 默认独立，均可由管理端字段转换规则配置。 |
| 每件均价 | 筛选范围内销售金额 ÷ 销量（件），单位：元/件。 |
| 到达市场日期 | 结算单到达市场的日期，列表和详情中用于展示。 |
| 销售日期 | 界面筛选和统计使用的日期口径，按销售明细日期计算。 |

# 2. 产品概述

SLD-水果市场销售分析是面向果农的水果销售分析工具。系统围绕 A/B/C 三级的销量、销售额、每件均价和数量占比，提供「录单/导入 → 二次确认 → 看板 → 单柜诊断 → 货柜/品牌对比 → 导出与顺仔问答」的完整链路；当前实现以结算单和品牌为分析主体。

## 2.1 核心能力

- 多文件导入：支持多张 XLSX 结算单，先解析为待确认草稿，用户确认后才写入销售明细、结算摘要和导入问题。
- 手工录单：支持手工录入结算单基本信息、销售明细、售后明细、费用明细，并自动暂存到服务端草稿。
- 销售看板：按销售日期和商号查看总销量、总销售额、每件均价及 A/B/C 等级结构与规格图表。
- 数据明细：按商号查看结算单列表、销售明细、只读复核、删除结算单和按行导出。
- 单柜与对比：查看每一张结算单的基础信息、等级结构、售后费用、每日趋势和同品牌对比。
- 品牌对比：按同品牌结算单勾选组合，自动识别单号系列，输出 A/B/C 独立指标、价差、图表和 AI 解读。
- 等级细分：将原始等级写法拆成大等级、号别和品质标记，形成价格阶梯。
- 导出与追溯：导出总览 CSV、结算单列表/单张结算单/手工单的 XLSX 与 PDF，并追溯销售明细来源文件。
- 站内通知：集中展示管理端发布给当前用户的通知，支持未读角标、单条已读和全部已读。
- 数据问答：右下角悬浮机器人「顺仔」支持自然语言查询销量、排名、明细和对比。

## 2.2 使用链路

1. 注册或登录系统。
2. 在「录单 / 导入」上传 XLSX 文件，或进入「手工录单」手动录入。
3. 在「卖得怎么样」查看整体经营情况。
4. 在「每一单」和「结算单详情」核对每一张结算单。
5. 在「结算单对比」和「品牌对比」进行横向分析。
6. 需要留存或上报时，使用导出功能生成文件。

# 3. 用户与登录

## 3.1 注册

- 用户以「用户名 + 密码 + 邮箱 + 邮箱验证码」注册，用户名最大 80 个字符，系统按忽略大小写去重。
- 密码至少 8 位，前端进行必填、长度和两次输入一致性校验。
- 注册前需输入有效邮箱并发送 6 位验证码，验证通过后才创建账号。
- 注册成功后自动创建登录会话，并跳转到原目标页面。

## 3.2 登录与免登录

- 登录支持使用用户名或邮箱，用户名匹配忽略大小写。
- 默认登录有效期 7 天。
- 勾选「30 天内免登录」后，服务端会话与浏览器 Cookie 均延长至 30 天。
- 登录失败统一提示「用户名或密码错误」，避免泄露账号是否存在。
- 已禁用账号登录时提示「该用户已被禁用」。

## 3.3 忘记密码

- 用户可在登录页进入「忘记密码」。
- 输入注册邮箱后发送 6 位验证码。
- 验证通过后设置新密码，完成后返回登录页。

## 3.4 退出与鉴权

- 业务页面均要求登录；未登录访问时跳转登录页，并携带 redirect 返回地址。
- 退出登录会撤销服务端会话并删除 HttpOnly Cookie。
- 登录、注册页面对已登录用户自动跳转业务首页，避免重复登录。
- 无任何可访问菜单的账号登录后提示联系管理员授权。

# 4. 工作台与导航

## 4.1 主导航

面向果农的主导航收敛为三个入口：

- 卖得怎么样：对应「销售总览」。
- 每一单：对应「数据明细」。
- 录单 / 导入：对应「文件导入」，并可从页头进入「手工录单」。

其余功能收进「更多」：

- 结算单详情、结算单对比、品牌对比。

## 4.2 工作台外壳

- 顶部 header 显示品牌标识、当前页面、本地日期/星期/时分秒、当前用户名和退出按钮；手机端只显示时分秒。
- 桌面端左侧导航可收起为图标栏，状态保存在 localStorage。
- 页签栏记录本次会话打开过的页面，首页固定不可关闭；其余页签可单个关闭或「关闭其他」。
- 页签状态只保留当前会话，登录或刷新后从首页重新开始，不缓存上次打开的页签。
- 业务页面向下滚动后显示「回顶部」悬浮按钮；手机端按钮自动抬到底部导航上方。

## 4.3 通知中心

- 顶部铃铛展示未读数量和角标。
- 点击铃铛展开通知列表，可查看通知详情。
- 支持单条已读、全部已读；紧急或重要通知可弹出横幅提醒。

## 4.4 响应式与字号

- 桌面端全局字号随视口宽度在 15px–17px 之间平滑缩放。
- 移动端固定 17px，避免固定 zoom 造成横向溢出。
- 手机端隐藏左侧导航，使用顶部 header + 底部大按钮导航；关键表格改为纵向卡片，复杂模块默认收起。
- 字号偏好可通过外壳控件调整，并保存在本地。

# 5. 数据录入

## 5.1 支持的文件

- 仅支持 .xlsx，可一次上传多个文件。
- 单个文件最大 20 MiB；不支持的文件格式会被前端忽略或由后端拒绝。
- 支持点击选择文件和拖拽文件到上传区域；手机端点选文件。

## 5.2 导入二次确认

- 上传后先进入「二次确认」页，系统只创建导入草稿，不写入正式销售事实。
- 用户可逐文件核对基础信息、销售明细、售后明细和费用明细，发现问题行标红。
- 可修改草稿并自动保存；确认提交后才写入批次、源文件、销售记录、结算摘要和数据问题。
- 有错误或商号冲突时，需二次确认后强制提交。

## 5.3 解析规则

- Excel 从表头上方读取「商号 / 单号 / 柜号 / 转运车号」。
- 通用表头支持：商号、单号、柜号、销售日期、品种/规格、等级、数量、单价、金额。
- 兼容元数据位于表头上方、日期合并或仅首行填写、等级写在品种规格中的版式。
- 等级映射由管理端字段转换规则动态生成；默认 BC → C，AB 默认独立。
- 缺字段或未知等级的行不写入销售事实；其他有效行继续导入，并生成问题明细。
- 商号缺失的文件会被拒绝。

## 5.4 单号与商号展示规则

- 单号双写：原始单号与适配后单号同时保存。适配规则将「宝贝003 → 宝贝-003」「宝贝L004 → 宝贝-004」，页面、导出和导入记录统一展示适配后写法。
- 商号双写：原始商号与适配后商号同时保存。适配规则去除开头重复「单」前缀，例如「单637 → 637」。页面统一展示适配后商号，原始商号通过提示或副标题保留追溯。
- 商号仍作为结算单唯一业务键和接口参数，选择器和分享链接使用原始商号。

## 5.5 重复导入与覆盖

- 同一商号再次上传时，返回「已存在待确认」。
- 用户确认后在同一事务内替换旧结算单；未确认不会覆盖。
- 上传期间页面显示等待遮罩和「正在导入，请稍候」，按钮禁用，避免重复提交。

## 5.6 导入记录与问题

- 导入记录展示文件名、商号、单号、导入时间、状态、成功/警告/失败行数。
- 问题明细可按批次展开查看，也可下载问题 CSV。
- 问题明细包含行号、级别、类型、字段、说明和原始值。
- 警告问题可标记为「确认无误」，确认后不再计入未处理警告数。

## 5.7 手工录单

- 在「录单 / 导入」页可进入「手工录单」，也可从导入记录继续未完成的手工草稿。
- 支持录入基本信息、销售明细、售后明细、费用明细和汇总信息。
- 草稿自动暂存到服务端数据库，刷新后可恢复；保存成功后清除草稿。
- 商号冲突时提示覆盖确认；同一手工单可再次修改并留痕。
- 录入时自动计算总件数、总金额、费用合计、应付金额等，并与来货数量进行差异提示。

# 6. 销售总览

## 6.1 页面作用

查看筛选范围内所有结算单的总体销量、销售额、每件均价，以及 A/B/C 三级的销售情况。

## 6.2 筛选与刷新

- 销售日期起止：选择后点击「查看结果」刷新。
- 商号下拉：切换后立即刷新；默认「全部结算单」。
- 不选择销售日期时查看全部数据。
- 起止日期校验：开始日期不能晚于结束日期。

## 6.3 指标展示

- 总销量：筛选范围内销量之和。
- 总销售额：筛选范围内销售金额之和。
- 每件均价：销售金额 ÷ 销量（件）。
- A/B/C 卡片：分别展示销量、销售额、每件均价和数量占比。

## 6.4 等级图表

- 展示等级件数结构、各等级每件均价和各等级各规格件数/均价。
- 全部结算单与单商号共用同一等级图表接口，商号切换后图表同步刷新。

# 7. 数据明细

## 7.1 页面作用

按商号查看每张结算单的销售额、各等级件数和每件均价，并可展开查看全部销售明细。

## 7.2 筛选与分页

- 商号下拉：切换后立即刷新，默认「全部结算单」。
- 销售日期起止：点击「查看结果」刷新。
- 支持按商号、单号、柜号、车牌关键字模糊搜索。
- 列表支持分页，每页 10 / 20 / 50 条。

## 7.3 列表内容

- 列包含商号、单号、柜号、到达市场日期、销售日期、A/B/C 件数、销售额、每件均价和记录数。
- 可点击「查看明细」查看该结算单每条销售记录。
- 可对单张结算单执行「导出」和「删除」操作。

## 7.4 查看明细

- 「查看明细」复用导入二次确认页的只读模式，可查看基础信息、销售明细、售后明细、费用明细和汇总信息。
- 只读模式禁用输入、隐藏新增/删除/还原/提交按钮。

## 7.5 删除结算单

- 删除录错的结算单时，连带移除销售明细、售后、费用、汇总和修改留痕。
- 删除操作需确认，误删不可在页面撤销，请谨慎操作。

# 8. 结算单详情

## 8.1 页面作用

选择一张结算单，查看基础信息、销量、销售额、等级情况、售后与费用、每日趋势、同品牌对比及来源追溯。

## 8.2 筛选与默认选中

- 商号下拉切换后自动刷新；默认选中第一张可用结算单。
- 销售日期起止：点击「查看结果」刷新。

## 8.3 核心内容

- 基础信息：市场、单号、到达市场日期、销售日期、柜号、转运公司。
- 关键指标：销量、销售额、每件均价等。
- 等级销售情况：A/B/C 的销量、金额、每件均价和占比。
- 每日趋势：该结算单按销售日期统计的销量与每件均价。
- 售后与费用：展示售后金额、售后比、市场费用、费用明细、应付金额等。
- 来源追溯：查看销售明细，并追溯每条记录对应源文件。

## 8.4 同品牌对比与 AI 解读

- 与同品牌其他结算单对比各等级每件均价差异。
- 可生成当前结算单与同品牌其他结算单的经营解读，数字取自系统已有数据。

# 9. 结算单对比

## 9.1 页面作用

按销售日期查看各结算单（按商号归集）的销量、销售额和每件均价。

## 9.2 操作方式

- 选择销售日期起止，点击「查看结果」。
- 结果支持按销售额、销量或每件均价排序。

## 9.3 展示内容

- 每张结算单展示商号、单号、柜号、销售额、销量、每件均价。
- 同时展示 A/B/C 各等级的等级、每件均价和占比。
- 移动端适配为紧凑卡片，保证信息可读。

# 10. 品牌对比

## 10.1 页面作用

勾选同一品牌下的两张及以上结算单，按 A/B/C 等级分别核算件数、金额和每件均价，并进行品牌汇总和等级细分分析。

## 10.2 选择结算单

- 先选择品牌，再选择该品牌下的结算单。
- 支持搜索商号、单号、柜号，按系列折叠或按最近到达日期排序。
- 勾选状态为草稿，点击「确定」才触发一次对比请求。
- 已选组合写入地址栏 selected 参数，可分享或还原。
- 至少选择两张结算单才能对比；一次最多选择 6 张用于 AI 分析。

## 10.3 品牌约束

- 对比和 AI 分析均要求所选结算单属于同一品牌。
- 跨品牌选择时后端返回 422，前端选择器已按品牌约束候选范围。

## 10.4 对比结果

- 结算单总览表：逐张展示件数、金额、每件均价和 A/B/C 结构。
- 品牌汇总：同一品牌的多张结算单合并查看。
- A/B/C 独立表：每个等级单独展示件数、金额、每件均价和金额占比。
- 等级价差：展示 A、B、C 每件均价，A-B 价差、B-C 价差和 B 比 A 折价比例。
- 图表：按 A/B/C 展示每件均价对比和数量/金额结构对比。

## 10.5 等级号别视图

- 按等级号别查看价格阶梯，例如 A5、B6/7 等。
- 原始等级按「大等级 + 数字号别」解析；区间写法原样保留，例如 B6/7。
- 品质标记（熟、裂、黄皮）只做标记，不参与分桶。
- 无法识别的写法归入「其他」，单独提示且不计入上述阶梯。
- 可展开数据表，查看每个号别的件数、金额、每件均价、件数占比和金额占比。

# 11. AI 分析与顺仔问答

## 11.1 顺仔数据问答

- 右下角悬浮机器人「顺仔」支持自然语言提问，回答数字全部取自系统现有数据。
- 大模型按问题选择 overview / rank / detail / compare 等只读工具，最多多轮追问后返回答案、步骤和模型。
- 系统没有的字段（如采购成本、利润）会直接说明，不虚构。
- 仅拥有 ask:view 权限的角色可见；无权限时前后端双层拦截。
- 对话窗打开时与「回顶部」按钮互斥避让，按 Esc 或按钮可收起。

## 11.2 AI 分析结论

- 单柜详情：生成当前结算单与同品牌其他结算单的价格对比和经营建议。
- 品牌对比「按系列」视图：生成所选结算单的整体对比解读。
- 品牌对比「按等级号别」视图：生成等级细分解读。
- 相同筛选条件会直接返回后端缓存；可手动刷新重新生成。
- 后端先计算对比指标，AI 仅解读结果，避免自行重算产生口径偏差。
- AI 未配置或调用失败时，不影响其他页面和数据分析功能。

## 11.3 结论结构

结论按「结论 + 比较 + 建议」组织，并结合关键数字高亮展示，便于直接阅读。

# 13. 指标口径与业务规则

## 13.1 核心指标

| 指标 | 计算公式/规则 |
| --- | --- |
| 销售数量 | 筛选范围内 quantity 之和，单位为件。 |
| 销售金额 | 筛选范围内 amount 之和。 |
| 每件均价 | 销售金额 ÷ 销售数量（件）；数量为 0 时为空，单位元/件。 |
| 数量占比 | 某等级销售数量 ÷ 同筛选范围总销售数量。 |
| 金额占比 | 某等级销售金额 ÷ 同筛选范围总销售金额（品牌对比使用）。 |
| B 比 A 折价 | (A 每件均价 - B 每件均价) ÷ A 每件均价；A 每件均价存在且 B 每件均价存在时计算。 |

## 13.2 等级规则

- A/A6 → A；B/B6 → B；C/C6/BC/BC6 → C。
- AB 默认独立，可由管理端配置为归入 A。
- 界面显示为「C 果（含 BC）」。
- 原始 BC 等级不保留为独立展示等级，但原始等级信息可追溯。

## 13.3 日期与结算单规则

- 日期筛选按销售日期计算，不按导入时间。
- 未指定日期时，数据明细默认取最新销售日期往前一个自然月。
- 结算单以商号为唯一业务键；柜号仅作为车柜标识。

## 13.4 异常识别规则

| 异常类型 | 触发条件 |
| --- | --- |
| 每件均价偏低 | 至少 2 张结算单，且当前结算单每件均价低于同期整体每件均价的 80%。 |
| 等级销量占比偏离 | 至少 2 张结算单，且某等级销量占比较同期整体偏离超过 25 个百分点。 |
| 日销量偏离 | 至少 3 个销售日，且某日销量较同期中位数偏离超过 50%。 |

# 14. 安全与权限

- 业务页面和 API 均要求登录；公开演示页 /preview 不包含真实业务数据。
- 密码使用 Argon2 哈希存储。
- 登录会话使用服务端会话，数据库仅保存 token 的 SHA-256 哈希。
- 浏览器通过 HttpOnly Cookie 携带凭证，前端脚本无法读取。
- 用户名登录忽略大小写；错误提示不泄露账号是否存在。
- 会话可服务端撤销，退出登录会删除会话并清除 Cookie。
- 菜单、角色和权限由管理端统一维护，业务端只读派生；停用菜单整项隐藏。
- 顺仔问答、手工录单、导出等敏感能力均有对应权限点控制。
- 非测试库禁止执行 DROP TABLE / DROP DATABASE / DROP SCHEMA / TRUNCATE 等破坏性元数据操作。

# 15. 非功能特性

## 15.1 前端技术特点

- Vue 3 + Vue Router + Vite，无状态管理库、无 UI 组件库、无图表库。
- 图表由手写 SVG 组件实现，保证移动端适配和主题一致性。
- 图表统一提供跟随式提示，提升可读性。
- 业务路由按需懒加载，图标深导入，降低首屏资源体积。
- 部署后旧哈希分片失效时，自动整页重载到目标路由，避免菜单点击无响应。

## 15.2 后端技术特点

- FastAPI + SQLAlchemy 2.0 + MySQL，单体前后端分离应用。
- 导入文件保存在后端 uploads 目录，业务数据入库；真实附件不入 Git。
- 金额使用 Decimal 计算，导出时做表格公式注入防护。
- 统一日志记录 method / path / status / duration_ms / request_id，未捕获异常写 exception。

## 15.3 可用性

- 桌面端与移动端均完成响应式适配。
- 关键异步操作提供加载态、空状态和错误重试入口。
- 导入上传、明细弹窗、选择器抽屉等关键交互具备键盘/焦点和 aria 支持。
- 前端日志对敏感字段自动脱敏。
