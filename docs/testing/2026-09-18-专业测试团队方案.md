# 专业测试团队与测试方案

> 状态：四组测试已回传并完成全量可执行验证；下一步统一修复，暂不改代码。
> 最后更新：2026-09-18

## 一、团队结构

| 角色 | 职责 | 当前执行方式 |
| --- | --- | --- |
| 测试组长 | 制定范围、分配小组、优先级排序、汇总问题、输出整改建议 | 本轮主会话 |
| 用户端功能测试组 | `fruits_ana` 用户链路与业务口径 | 并行测试代理 |
| 管理端功能测试组 | `fruits_ana_admin` 权限、配置与业务管理链路 | 并行测试代理 |
| 性能与稳定性测试组 | 两系统前端性能、接口/查询效率、构建与移动端体验 | 并行测试代理 |
| 业务一致性测试组 | 两系统共享数据、等级映射、通知、审计与跨系统影响 | 并行测试代理 |

## 二、测试范围

- 用户端：认证、导入/二次确认、总览、趋势、结算单列表/详情/对比、系列对比、等级细分、顺仔问答、导出、通知、移动端体验。
- 管理端：登录/RBAC、用户/角色/菜单/权限、通知、录单字段配置、字段转换配置、业务数据、审计日志、系统配置。
- 性能：构建产物、路由懒加载、接口响应、查询热点、大数据量渲染、控制台/网络异常、移动端溢出。
- 业务一致性：共享 MySQL 数据、等级映射规则影响、单号/商号口径、回款/费用/清关展示、审计留痕、跨系统权限。

## 三、测试视角

- 业务正确性：数据口径、公式、规则是否与 README/ARCHITECTURE/DECISIONS 一致。
- 用户可用性：操作路径是否合理、反馈是否清晰、错误是否可恢复。
- 合理性：对果农用户是否过载、术语是否易理解、冗余步骤是否必要。
- 风险：是否影响数据安全、覆盖导入、误操作、权限越权。

## 四、验证方式

- 静态审查关键代码与测试。
- 执行现有后端 pytest、前端 test/typecheck/build。
- 有可用环境时用 curl / 构建产物做轻量接口与页面检查。
- 不修改业务代码；问题统一上报测试组长，由组长排序后决策是否修复。

## 五、输出

问题按以下字段汇总：

1. 编号
2. 系统
3. 模块/页面
4. 严重级：P0 阻断 / P1 严重 / P2 一般 / P3 建议
5. 现象
6. 用户影响
7. 证据/复现路径
8. 整改建议
