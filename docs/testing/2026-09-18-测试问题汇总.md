## 三、P0 必须立即处理

### P0-1 导入复核始终 `force=true`，覆盖旧结算单缺少真正二次确认
- 系统：`fruits_ana`
- 现象：`ImportReviewView.vue` 的 `doSubmit()` 默认 `force=true`，模板按钮也固定传 `true`，从未先以 `force=false` 让后端返回 409 冲突。
- 用户影响：同一商号再次导入时可能直接删除旧 `ImportBatch` 并覆盖销售明细/汇总，用户看不到覆盖确认。
- 证据：`frontend/src/views/ImportReviewView.vue:302`、`backend/app/services/import_draft_service.py:654`
- 建议：首次提交 `force=false`，展示冲突后二次确认再发 `force=true`。

### P0-2 管理端对共享业务表执行 `create_all`，存在建出旧版缺列表结构风险
- 系统：`fruits_ana_admin` 与 `fruits_ana` 跨系统
- 现象：管理端 `import_batch`、`sale_record`、`settlement_summary`、`data_issue` 是旧版只读子集，启动时无条件 `create_all`。
- 用户影响：共享库重建/新环境若先启动管理端，会创建缺少用户端关键列的表，用户端导入/录单/对账失败。
- 证据：`fruits_ana_admin/backend/app/main.py:29`、`fruits_ana_admin/backend/app/db.py:158`、`fruits_ana_admin/backend/app/models.py:77`
- 建议：共享业务表禁止管理端 `create_all`；表结构统一由用户端迁移脚本管理。

## 四、P1 严重问题摘要

### 用户端功能
1. CSV 上传入口接受，但新模板解析器固定 `read_excel`，CSV 会失败。
2. 多文件预览被前端静默降级为单文件，提示不可见，存在漏导风险。
3. `attachments/结算单模板样式.xlsx` 缺失，手工单/列表逐行导出 500；全量后端 236 项中 4 项因此失败。

### 管理端功能
4. 控制台权限退化为“有 `admin_access` 即全权限”，`is_super_admin` 未参与判断。
5. 每次启动 `seed_admin_data` 重置菜单、角色授权、字段选项和转换规则，配置保存后重启丢失。
6. 启动时硬编码恢复 `test` 用户超级管理员权限，无法通过页面永久收回。
7. 创建用户审计日志明文记录 `password`。
8. 系统配置页的注册开关/会话天数/密码长度配置未接入认证逻辑，修改无效。

### 性能与稳定性
9. 看板/详情初始无默认日期，可能全表扫描 `SaleRecord`。
10. 结算单列表“先全量后内存分页”，翻页不降低数据库扫描。
11. 多个页面重复加载全量结算单候选。
12. 单柜销售明细全量返回并全量渲染。
13. 管理端通知列表每行 2 次统计查询且返回完整 `content`。
14. 管理端角色/用户列表存在 N+1 查询。
15. 通知富文本允许 2MB Base64 图片，但数据库列为 `Text`，存在截断/500 风险。

### 业务一致性
16. 管理端改字段转换规则后，历史 `sale_record.grade` 不重算，新旧口径混用。
17. 转换规则目标值允许 `Z`/`XYZW`，用户端静默归 `OTHER`，无告警。
18. 旧导入与新导入/手工单对结算主字段“文件值/计算值”语义相反。
19. 售后金额正负号在旧导入与新链路之间不一致。
20. 新模板导入与手工录单未补齐清关税费字段。
21. `force=true` 可跳过 error 级阻断，仍可能解析异常返回 500。
22. 导入单与手工单可互相按商号覆盖，且部分覆盖不留审计。

## 五、P2/P3 摘要

- 通知：定时发布无状态机；全部已读可能标记未到期通知；目标用户 ID 未校验；全员通知新增用户漏收。
- 业务数据：总览数据质量问题不随筛选联动；AI 缓存删除无审计；管理端业务数据分页/筛选不足。
- 数据口径：归一化商号无唯一约束；录单字典禁 `BC` 与用户端 `AB/BC` 支持矛盾。
- 交互：管理端移动端表格未启用卡片模式；用户端录单/复核窄屏仍固定 1080px；使用手册按钮无动作。
- 稳定性：前端请求无超时/取消；系列对比 GET 未限制商号数量；缺少统一异常处理。
- 文档/演示：公开演示页硬编码数据且轮询受保护通知接口；管理端 README 与实际能力不一致。

## 六、组长建议的整改顺序

1. 先修两个 P0：导入复核覆盖确认、管理端共享表 `create_all`。
2. 再处理用户端导入/导出阻断：CSV、多文件、导出模板。
3. 再处理管理端权限/配置持久化：种子覆盖、`test` 账号、控制台授权、审计脱敏。
4. 再统一跨系统业务口径：等级重算、金额主字段语义、售后正负号、清关字段、覆盖审计。
5. 最后做性能/体验整改：后端查询下推分页、去 N+1、大字段处理、移动端表格。

## 九、统一修复结果（2026-09-18）

> 本阶段已从“全量测试”进入“统一修复”，修复范围覆盖两个仓库，仍未提交 Git。

### 已修复

- **用户端**：导入复核首次 `force=false`，冲突后再显式确认；恢复多文件选择并展示 `failures`；CSV 模板解析分支；导出模板改为内存生成，修复 4 个后端失败。
- **用户端通知/总览/展示**：全部已读只处理当前可见通知；数据质量计数随日期/商号筛选，且默认按最新销售日期往前一个月窗口过滤；公开演示页标注演示数据，不再轮询受保护通知接口；底部“使用手册”改为管理员获取提示并补样式。
- **管理端**：共享业务表禁止 `create_all`；种子只补缺不覆盖、移除 `test` 强制授权；RBAC 按 `is_super_admin`/角色/权限点计算；创建用户审计不记密码；系统配置接入会话与密码策略；通知目标校验返回 422；AI 缓存删除增加审计。

- **跨系统口径**：字段转换目标值只允许合法等级；规则变更页提示历史等级不重算；售后金额统一为非负口径；导入/手工单按 `source_type` 防止互相覆盖；商号归一化冲突检测；AI/导出同步售后绝对值。
