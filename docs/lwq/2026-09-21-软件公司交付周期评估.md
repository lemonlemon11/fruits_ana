# SLD-水果市场销售分析系统：软件公司交付周期评估

文档版本：V1.0  |  编制日期：2026-09-21

## 1. 结论

若整套平台交由软件公司从零交付，配备：

- 1 名高级开发工程师
- 1 名高级运维兼测试兼需求分析工程师

推荐合同交付周期为 **8–10 周，约 2–2.5 个月**。

- 顺利推进且需求稳定时：最快约 **6–8 周**。
- 需求频繁变更、历史数据质量差或验收周期拉长时：预留到 **10–12 周**。

## 2. 评估口径

本次评估范围以当前系统已完成能力为准，不含二期能力：

- 数据导入与二次确认、手工录单。
- 销售总览、结算单详情、单柜诊断、结算单/品牌对比、系列对比、等级细分。
- 顺仔自然语言问答与多页面 AI 分析。
- 登录注册、角色权限、菜单控制、站内通知。
- CSV / XLSX / PDF 导出、来源追溯。
- 桌面端与移动端响应式适配、生产部署与运维。

## 3. 工作量测算

| 工作项 | 高级开发 | 高级运维/测试/需求 | 说明 |
| --- | --- | --- | --- |
| 需求调研、原型与口径确认 | 2–3 | 3–5 | 结算单口径、等级映射、页面验收标准 |
| 项目初始化、数据库与部署 | 2–3 | 2–3 | FastAPI + Vue + MySQL + Nginx + 测试环境 |
| 数据模型与迁移 | 3–4 | 1–2 | 25 张核心表、单号/商号/等级口径 |
| 文件导入与二次确认 | 5–6 | 2–3 | 多文件、草稿、问题管理 |
| 手工录单与导出 | 2–3 | 1–2 | 表单、草稿、模板 |
| 看板、对比与等级分析 | 6–7 | 2–3 | 核心分析链路与图表 |
| AI 问答与分析 | 3–4 | 1–2 | function calling、缓存、权限 |
| 权限、通知与账号体系 | 2–3 | 1–2 | 认证、RBAC、菜单、通知 |
| 移动端与视觉优化 | 2–3 | 1–2 | 响应式、卡片化、字号、主题 |
| 联调、测试、回归、文档 | 2–3 | 5–7 | 自动化测试、浏览器回归、UAT、交付文档 |
| 生产部署、上线与移交 | 1–2 | 3–5 | 部署、备份、日志、验收 |
| **合计人日** | **30–38** | **22–35** | 总计约 52–73 人日 |

商务报价建议按 **60 人日** 打包测算，即两名工程师各 30 人日。

## 4. 建议日历排期

| 阶段 | 周期 | 关键产出 |
| --- | --- | --- |
| 需求与设计 | 第 1–2 周 | 需求确认单、原型、数据库设计、接口契约 |
| 工程环境 | 第 2 周 | 开发/测试环境、CI、部署脚本 |
| 核心数据链路 | 第 2–5 周 | 数据模型、导入、二次确认、手工录单 |
| 分析与 AI | 第 3–7 周 | 看板、对比、等级细分、顺仔问答 |
| 权限与体验 | 第 4–8 周 | 账号、权限、通知、导出、移动端 |
| 集成测试与 UAT | 第 7–9 周 | 测试报告、验收问题修复 |
| 上线与移交 | 第 9–10 周 | 生产部署、备份、培训、交付文档 |

关键路径为「需求 → 数据导入 → 看板/对比 → AI → UAT → 上线」，其中数据导入、对比分析和真实数据 UAT 是主要风险点。

## 5. 与当前系统实际节奏的对比

当前仓库从 2026-09-08 到 2026-09-21 共 92 个提交，14 个自然日内完成主链路并进入上线前收口。该节奏依赖 AI 辅助编码、高频会议推进和多轮并行修改，明显快于传统软件公司常规交付，不应作为常规商务排期基准。

按常规两人团队测算，去掉等待、真实环境验收和交付缓冲后，纯实施约 35–43 人日；增加项目管理、客户等待、UAT、上线与文档后，打包为 60 人日、8–10 周日历周期更稳妥。

## 6. 主要风险与缓冲建议

- 历史结算单格式不规则，导入解析与清洗可能增加 3–5 人日。
- 微信生态认证、域名备案、SSL、云资源开通存在外部等待，建议提前并行办理。
- 大模型接口、Prompt 与答案质量需要多轮验证，建议预留 2–3 人日。
- UAT 数据未准备或业务口径反复调整，是交付周期最大的不确定因素。
- 建议合同中明确需求变更流程、验收标准和数据提供责任，避免无限期拖长。
