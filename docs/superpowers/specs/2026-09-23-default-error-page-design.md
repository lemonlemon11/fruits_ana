# 默认错误页设计

## 目标

为现有 Vue 工作台增加统一错误恢复入口。当系统级故障导致当前页面无法继续工作时，进入与现有外壳一致的错误页；业务校验、冲突和写操作失败仍留在原页面，避免丢失上下文或重复提交。

## 触发边界

- 页面读取请求（GET/HEAD）发生网络错误、超时、无效响应或 HTTP 500/502/503/504：进入错误页。
- 路由懒加载失败：先沿用现有逻辑自动刷新一次；再次失败后进入错误页。
- Vue 渲染异常、未处理的脚本异常或 Promise rejection：进入错误页。
- 未知前端路径：显示 404 模式。
- 已登录用户访问无权限页面：显示 403 模式。
- HTTP 401：清除前端会话并跳转登录页，不进入错误页。
- POST/PUT/PATCH/DELETE 失败、400/409/422、通知等后台读取失败：保留当前页面的局部提示，不自动跳转。

## 状态与恢复

- 错误状态只保存 `kind / from / status / requestId / occurredAt / source`，不保存堆栈、响应体或敏感字段。
- 状态写入 `sessionStorage`，带有效期；直接刷新 `/error` 仍能恢复错误编号和来源页面。
- “重新加载”使用来源路径进行整页重载；“返回首页”根据当前角色菜单选择首个可访问页面。
- 错误页不发起业务 API 请求，避免服务故障时形成跳转循环。
- 已登录状态下保留工作台外壳；会话恢复本身失败时使用独立品牌页。

## UI 与可访问性

- 复用现有颜色、字号、边框和移动端断点，不新增平行设计系统。
- 使用 Lucide 线性图标，不使用 emoji 作为结构图标。
- 主操作触控区域不小于 44px；保留键盘焦点；错误标题使用 `role="alert"` / `aria-live`。
- 详情区只展示错误类型、请求编号、发生时间和来源页面，可折叠，不暴露技术堆栈。

## 静态兜底

在 `frontend/public/error-static.html` 提供不依赖 Vue、API 或外部资源的静态页面，供部署侧配置 Nginx `error_page 500 502 503 504`。仓库只交付静态资源和配置说明，不在本次修改生产 Nginx。

## 验证

- 纯函数测试覆盖错误分类、安全来源路径、状态过期和文案映射。
- API 客户端测试覆盖 Request ID、HTTP 503、网络错误和写请求不触发跳转。
- 源码测试覆盖 `/error`、catch-all、全局异常处理和错误页无 API 依赖。
- 执行前端 test、typecheck、build；浏览器检查桌面与 390px 移动端无横向溢出。
