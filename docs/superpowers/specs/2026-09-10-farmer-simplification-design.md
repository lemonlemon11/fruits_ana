# 果农版界面简化设计（方案 B：大卡片 + 单一详情流）

- Date：2026-09-10
- Status：第一层已实现；第二层待实现
- 目标人群：果农。文化水平不高、不熟悉电脑，主要在手机上看，也会用电脑。
- 用户原话：「所有的操作都要简单化，数据阅读需要明显」。

## 设计原则

1. **一屏一个重点**：每页第一个元素是最大数字，其余信息按重要性递减。
2. **数字要大到不用眯眼**：金额/件数用大号等宽数字，重要数字 ≥ 32px，首页主数字 52–76px。
3. **好坏用颜色和箭头说话**：`↑ 比别的单高 2%` / `↓ 比别的单低 4%`，不要求用户理解百分比口径。
4. **白话**：不用「同期基线 / 中位数偏离 / 销量占比 / 平均每件售价」等术语。
5. **操作不超过两步**：默认显示全部数据，筛选是可选项；主操作按钮只有一个且很大。

## 第一层：已完成（2026-09-10）

### 导航简化
- 主导航由 6 项收敛为 3 个大入口：`卖得怎么样`（/overview）、`每一单`（/settlements）、`数据导入`（/imports）。
- `结算单详情 / 结算单对比 / 系列对比` 收进侧栏「更多功能」，不再与主入口平级。
- 手机端改为底部固定大按钮导航（3 个主入口 + 「更多」），高度固定 `--mobile-tabbar-height: 92px`；
  原汉堡菜单按钮移除，「更多」面板改为底部弹出层，位于导航之上。
- 代码：`frontend/src/AppShell.vue`、`frontend/src/styles-shell.css`。

### 字号与触控基线
- `:root { font-size: 17px }`；全站最小字号 **0.85rem ≈ 14.4px**（原先低至 10–11.5px）。
- 表格正文 `.72rem → 1.05rem`，按钮/输入框最小高度 `44px → 52px`，导航项 `52px → 64px`。
- 关键数字放大：等级/汇总数字 `1.18rem → 1.7rem`，指标值 `.92rem → 1.2rem`，图表坐标轴 `.58rem → .85rem`。
- 覆盖文件：`styles.css`、`styles-dashboard.css`、`styles-shell.css`、`styles-responsive.css`、
  `styles-auth.css`、`TrendChart.vue` 及其余组件/视图的 `<style>` 段（`OverviewView.vue` 除外，见下）。

### 验收证据（Playwright + Chromium，2026-09-10）
- 16 项检查全部通过：主导航 3 大入口、导航字号 19.55px/高度 64px、各页最小字号 14.4px、
  桌面与手机均无横向溢出、手机底部导航常驻（按钮高 75px）且「更多」面板不被遮挡。

## 验收方式

- 每个页面：桌面 1440px + 手机 390px 截图对照设计稿；最小字号 ≥ 14px；无横向溢出。
- 关键交互：主操作 2 步内完成；下拉框选项可读；错误提示含「怎么办」。
- 自动化：沿用 `frontend/tests/farmer-ui-copy.test.mjs` 的文案约定测试 + Playwright 脚本。
