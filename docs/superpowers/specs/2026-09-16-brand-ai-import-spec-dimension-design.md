# 设计：品牌文件大模型解析 + 二次确认 + 规格/头数维度化

> 2026-09-16 · 关联计划 `docs/superpowers/plans/2026-09-16-brand-ai-import.md` · ADR-026 / ADR-027

## 1. 目标与边界

一次把两件事做透，避免「先改字段、再改分析、再改导入」三轮返工：

- A. 品牌文件解析：每个品牌一份提示词配置，**由大模型完成解析** → 解析成录单草稿 → **二次确认**后入库。
- B. 规格（KG）与头数从「录单附属信息」升级为**一等分析维度**，并且要能装下 `9/10`、`6/7`
  这类区间写法。

边界：本期品牌 香香 / 宝贝 / 晴牌（润控金象不做）；不做模型微调；不改动现有等级（A/B/C）
与日期口径。

## 2. 关键设计决策

| 决策 | 选择 | 理由 / 取舍 |
| --- | --- | --- |
| 区间值怎么存 | **原文文本 + 派生 min/max 数值列** | 原文保真、可展示可导出；min/max 让聚合可走数值列、可建索引，将来改口径不用回补数据 |
| 区间代表值（数值聚合用） | **取上限**（`9/10` → 10） | 客户按最大规格报价的习惯口径；可解释、无小数。存了 min/max，改中点/下限随时可切 |
| 分析分桶 | 由 min/max 生成**归一标签**：`10` / `9-10` | 与书写无关（`10KG`、`10kg`、`9-10` 各自稳定归桶），不合并不同规格 |
| 规格的唯一分析口径 | 统一走 `spec_kg`（含 min/max） | 现在文件解析写 `spec_raw`、手工录单写 `spec_kg`，两条链路口径不一致，必须收敛到一个字段 |
| 开发期数据 | **不做迁移，清库重导** | 开发阶段，迁移脚本成本 > 收益；重建后由 `tickets/` 重新导入 |
| 解析策略 | **大模型为主解析路径**，规则只做归一与校验 | 文件写法高度不规范（后缀开放词表、括号可能装后缀、括号可能不闭合），规则穷举必然失败；模型负责"照抄槽位"，代码负责算数与判定 |

## 3. 数据模型（`sale_record`）

| 列 | 现在 | 改为 | 用途 |
| --- | --- | --- | --- |
| `spec_raw` | `String(255)` | 不变 | 单元格**逐字原文**（如 `A3（9/10KG)尾`），只做溯源，不参与计算与展示主口径 |
| `spec_kg` | `Numeric(18,2)` | **`String(32)`** | 规格（KG）**归一后的规范值**：`10`、`9/10` |
| `spec_kg_min` / `spec_kg_max` | 无 | 新增 `Numeric(18,2)` NULL | 分析聚合、排序、分桶 |
| `piece_count` | `Integer` | **`String(32)`** | 头数**归一后的规范值**：`3`、`6/7` |
| `piece_count_min` / `piece_count_max` | 无 | 新增 `Numeric(18,2)` NULL | 分析聚合、排序、分桶 |

### 3.1 归一规则（唯一入口 `parse_spec_range()`）

`spec_kg` / `piece_count` 存的**不是逐字原文**，而是统一成 `min/max` 或单值的规范文本；
`9/10` 这类本来就规范的写法原样保留，其它写法一律收敛到同一形状：

| 文件/界面里的写法 | 规范值 | 说明 |
| --- | --- | --- |
| `9/10` | `9/10` | 已经是规范写法，原样保留 |
| `9-10`、`9~10`、`9～10`、`9—10` | `9/10` | 各种连接符统一成半角 `/` |
| `9/10KG`、`9-10kg`、`9/10 公斤` | `9/10` | 去掉单位 |
| `１０／９` | `9/10` | 全角转半角后按数值升序排列 |
| `10/9` | `9/10` | 端点统一升序，避免同一区间两种写法 |
| `10`、`10KG` | `10` | 单值不补 `/` |
| `9.5` | `9.5` | 小数保留 |
| `9/10/11`、`5/7/8` | `9/10/11`、`5/7/8` | 多段**原样保留**（客户 A4），数值端点取最小与最大 |
| 空、`—`、无法解析 | 留空 | 派生列置 NULL，并标红阻断保存 |

- 返回三元组 `(canonical, min, max)`；`canonical` 落库用于展示、回显与导出，
  多段写法按客户确认（A1~A4）原样保留（`3/4`、`5/7`、`5/7/8`），只做去字母与升序；
  `min` / `max` 供聚合与建索引，三者由同一次解析产出，不允许各算各的。
- 分桶标签：直接用 `canonical`（`10`、`9/10`），不引入 `9-10` 这种第二种写法。
- 文件导入链路（`settlement_parser` + 品牌解析器）与手工录单链路都走这个入口，
  于是「导入件没有件数」的旧假设作废。
- 展示统一：录单页、二次确认页、明细弹窗、导出 xlsx 一律显示规范值；
  需要追溯原始写法时看 `spec_raw`。

### 3.2 真实文件实测（`tickets/` 17 个 xlsx、501 行规格数据）

| 情况 | 行数 | 真实样例 |
| --- | --- | --- |
| 头数是区间 | 54 | `A3/4(10KG)`、`B3/4(9KG)尾/微裂`、`B7/5(大裂）`、`BC5/7/8（17KG）`、`A4/3(10KG)` |
| **KG 是区间** | **4** | `A3(9/10KG)`×2、`A3（9/10KG)尾`、`A3(10/11KG)Y硬包/不售后` |
| 括号未闭合 | 5 | `A5（19.5KG`、`A3/4（10KG`、`B6（19KG` |
| 无 KG 括号 | 若干 | `B7`、`A6`、`B6/7熟`、`C8/9大裂`、`A6熟/裂`、`B5` |

结论：`9/10KG` 这类「区间 + 单位」确实存在但很少（占 0.8%），集中在香香 3 个文件；
**区间的主战场是头数（54 行）**。因此解析器必须满足：

- 括号 `（）` / `()` 混用、**可以不闭合**（`A5（19.5KG` 要能解析出头数 5 + KG 19.5）；
- KG 段可能带单位、可能是区间（`9/10KG`、`10/11KG`）；
- 头数段可能三段（`5/7/8`）或降序（`B7/5`），归一后按 min/max 升序；
- 后缀可能含 `/`（`尾/微裂`、`硬包/不售后`），后缀整段进备注，**不参与区间拆分**；
- 等级前缀可能是双字母（`BC5`、`BC7/8`），按现有口径归 C；
- 头数段可能重复等级字母：`B3/B4(9KG)`、`C6/C8(17KG)`，归一后取 `3/4`、`6/8`；
- **括号里不一定装 KG**：`A5/6（熟）` 的括号内容是后缀「熟」，必须先判断括号内容是不是
  「数字 + 可选 KG 单位」，不是则整段当后缀，否则会把后缀误解析成规格；
- 后缀里可能出现无意义字符（`A3(10/11KG)Y硬包/不售后` 的 `Y`），原样进备注即可。

## 3.3 大模型与代码的职责边界

| 环节 | 归谁 | 说明 |
| --- | --- | --- |
| 抽取槽位（`A3(10/11KG)Y硬包/不售后` → 等级/头数/KG/后缀） | **大模型** | 唯一的解析路径；后缀是开放词表，规则不可能穷举 |
| 结构定位（哪张 sheet、明细区起止、费用/售后/清关行） | **大模型** | 一并交给模型判断，不用正则去猜版式 |
| 归一化（`9-10`→`9/10`、`B7/5`→`5/7`、全角转半角、去单位） | 代码 | 确定性、可回归测试 |
| 算数（金额 = 数量 × 单价、各项合计、应付总金额） | 代码 | 绝不让模型算数字，模型只抄文件原值 |
| 判定（等级归一 `BC`→C、销售行/非销售行） | 代码 | 规则固定 |
| 最终确认 | 人 | 二次确认页并排对照 + 合计对账 |

模型输出必须通过归一器与校验器；**过不了就标红，绝不猜**。

## 4. 计算层

- `analytics_core` 新增 `spec_metrics(records)` / `piece_metrics(records)`，镜像现有
  `grade_metrics()`：按桶返回 `{label, sales_quantity, sales_amount, weighted_avg_price,
  quantity_share}`，排序按桶的 `min` 数值升序。
- 新增标量指标：`avg_spec_kg` = Σ(数量 × `spec_kg_max`) / Σ数量，`avg_piece_count` 同理。
- 分桶缺失（min/max 为空）的记录统一进「未标注规格 / 未标注头数」桶，不参与标量指标。

## 5. 载荷与接口影响

逐个列出，避免漏改：

- `overview_service`：`grades` 同级新增 `specs` / `pieces`，并加两个平均指标。
- `settlement_analytics_service.get_grade_summary`：同上（单柜诊断数据源）。
- `series_analytics_service`、`grade_detail_service`：同上。
- `settlement_comparison`：对比维度新增「规格」横向对比（同一商号/不同柜的规格结构差异）。
- `ask_payloads` + `ask_tools`：顺仔问答工具支持按规格/头数查询与对比（口径与页面一致）。
- `ai_analysis_service` / `settlement_ai_analysis_service`：结论文案可引用规格/头数维度。
- `api/imports.py` 新增 `POST /api/imports/preview`：品牌 + 文件 → 草稿 + 问题清单，不落库。
- 新增 `parser/brand_profiles/`：香香 / 宝贝 / 晴牌配置，只放**版式说明与提示词**
  （单长什么样、列含义、输出 schema、few-shot 片段），不放"等级写法穷举规则"。

## 7. 解析与确认流程

1. 用户在导入入口选品牌 → 选文件。
2. `POST /api/imports/preview` 把整张表（按行文本化）连同该品牌的提示词交给大模型，
   由模型输出结构化槽位 JSON（等级 / 头数 / 规格 KG / 后缀 / 日期 / 数量 / 单价 / 金额 / 是否销售行），
   产出录单草稿 + 问题清单，全程不写库。
   **大模型是主解析路径**：不做"规则兜底"式的降级实现，模型不可用即提示不可用、不进入录单。
3. 二次确认页回填草稿，问题按「行 + 字段」标红并给原因；用户改完再保存。
4. 保存走现有 `POST /api/entry`（商号唯一键、覆盖逻辑、权限不变）。
5. 解析服务/模型不可用 → 明确提示不可用，不进入录单。

## 8. 校验与标红

必填缺失、金额 ≠ 数量 × 单价、明细合计 ≠ 文件合计、售后/费用/应付总金额对不上、
等级无法归一、日期无法解析、**规格或头数无法解析出数值区间**（不可解析即无法进统计）。

## 9. 开发期重建策略

- 不写迁移脚本：清库 → `init_db()` 建表 → 用 `tickets/` 文件重新导入。
- 破坏性 DDL 受 ADR-024 保护，清库必须显式开 `FRUIT_ANALYSIS_ALLOW_DESTRUCTIVE=1`
  并单独确认执行窗口；**由人工执行，不由代理自动跑**。

## 10. 分阶段实施

| 阶段 | 内容 |
| --- | --- |
| P0 | 数据模型 + 解析入口 + 录单链路（含前端输入与校验）、导出同步；清库重建 |
| P1 | 计算层 `spec_metrics` / `piece_metrics` + 各载荷扩展 + 前端展示（单柜诊断 / 货柜对比 / 看板） |
| P2 | 品牌配置 + `POST /api/imports/preview` + 香香解析（规则） |
| P3 | 二次确认页 + 标红 + 确认落库（端到端） |
| P4 | 宝贝 / 晴牌提示词配置 + 三品牌回归集 |

## 11. 验收

- 三品牌样例文件：解析结果与文件「销售金额 / 件数 / 应付总金额」一致。
- 区间规格 `9/10` 在预览页原样显示，在单柜诊断里归入 `9-10` 桶，标量指标按上限计入。
- 解析失败行标红，且未修正时不能保存。
- 现有等级、日期、加权均价口径不回归（回归测试全绿）。
