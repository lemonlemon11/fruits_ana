# 果农版页面重构设计

## 目标

将现有水果销售分析系统改造成适合文化水平较低、很少使用电脑的果农使用的界面。用户应能通过固定菜单找到四项核心工作，在每个页面内只处理当前任务，并从提示文字中直接知道“发生了什么”和“下一步怎么做”。

## 用户与使用原则

- 主要用户是果农，可能不熟悉电脑操作和专业数据分析词汇。
- 侧边栏是桌面端唯一的菜单入口；移动端使用同一组菜单的折叠菜单。
- 页面内不提供跳转到其他菜单的按钮、文字链接、卡片点击或标签页。
- 每页只保留一个主要操作，按钮使用明确的动作词。
- 筛选条件改变后不自动查询，用户选好条件后统一点击“查看结果”。
- 页面固定使用明亮、高对比度主题，不提供主题切换。
- 优先显示结论，复杂图表、销售明细、计算说明和来源追溯默认收起。
- 页面可见文案全部使用中文。结算单中的 A、B、C、BC 是业务等级代码，保留为“A果”“B果”“C果（含原始BC等级）”，并始终配中文说明；其余装饰标题、状态、按钮、图表标题和提示不得出现英文。

## 信息架构

系统保留四个一级菜单，名称和顺序固定：

1. 销售总览
2. 货柜对比
3. 货柜详情
4. 数据导入

桌面端左侧持续显示菜单和当前菜单状态。移动端顶部只显示品牌、当前菜单名和“打开菜单”按钮，展开后显示相同四项菜单。用户进入具体页面后，只能通过这组菜单前往其他页面。

## 通用页面结构

每个页面按以下顺序组织：

1. 页面名称和一句话用途说明。
2. “怎么查看”提示，使用“第一步、第二步”描述操作。
3. 当前页面的筛选或录入区。
4. 当前查看范围或操作状态。
5. 最重要的结果与结论。
6. 可选的“查看更多”折叠区，内容只属于当前页面。

表单控件保持可见标签，主要按钮高度不小于 44 像素。日期、数量、金额和单价都显示中文单位。颜色不单独承担含义，异常和成功状态同时提供文字说明。

## 页面设计

### 销售总览

用途是查看全部或指定货柜的销量、销售额、平均每件售价和等级表现。

- 筛选项：开始日期、结束日期、货柜。
- 主要按钮：`查看结果`。
- 当前范围示例：`当前查看：全部货柜，全部销售日期`。
- 首屏结果：总销量、总销售额、平均每件售价，以及 A果、B果、C果的销量、占比和平均每件售价。
- `查看更多销售数据` 默认收起，可展示每日变化、货柜排行和当前页面内的注意事项。
- 不显示“查看导入记录”“查看货柜详情”等跨菜单入口，货柜排行项不可点击跳转。

### 货柜对比

用途是选择二至三个货柜，在同一日期范围内比较销售表现。

- 筛选项：开始日期、结束日期、参加对比的货柜。
- 主要按钮：`查看结果`。
- 默认按销售额排序，允许在当前页面切换为按销量或平均每件售价排序。
- 结果以容易横向比较的列表或条形图展示，并直接写明单位与排名。
- 货柜行和图表仅用于选择、排序或查看当前页数据，不可跳转到“货柜详情”。
- 不足两个货柜时，提示用户至少选择两个货柜，并说明如何补选。

### 货柜详情

用途是选择一个货柜，查看该货柜的销售和结算信息。

- 筛选项：货柜、开始日期、结束日期。
- 主要按钮：`查看结果`。
- 首屏结果：货柜名称、销售日期范围、总销量、总销售额、平均每件售价和主要销售等级。
- 等级表现、销售变化和需要留意的问题使用通俗中文。
- 回款、费用、销售明细、计算说明和来源追溯放入默认收起的当前页区域。
- 删除页面内的总览切换、返回总览、前往导入等入口；没有货柜时只说明原因和下一步应在侧边栏选择“数据导入”。

### 数据导入

用途是上传结算单，并查看本次导入是否成功以及需要处理的问题。

- 首屏说明支持的文件类型和操作步骤，不使用技术术语解释上传过程。
- 主要按钮：未选文件时为`选择结算单`，选好后为`开始导入`。
- 上传后明确显示成功文件数、成功数据条数、重复数据条数和问题条数。
- 历史导入记录和问题明细属于本页，可保留并默认收起次要列。
- 下载问题明细属于当前页操作，可以保留；删除“查看销售分析”等跨菜单入口。

## 文案规则

### 名称与指标

- `经营总览` 改为`销售总览`。
- `单柜详情`、`单柜经营诊断`改为`货柜详情`。
- `导入数据`改为`数据导入`。
- `加权均价`改为`平均每件售价`，辅助说明为`销售额除以销量`。
- `销售量`统一为`销量`，避免同一指标出现多个名称。
- 英文装饰性小标题全部删除，不以中文音译替代。

### 状态与错误

状态提示采用“结果 + 下一步”的固定结构：

- 没有数据：`当前选择的日期没有销售数据。请调整日期后再次点击“查看结果”。`
- 查询失败：`销售数据没有加载成功。请检查网络后点击“重新查询”。`
- 日期错误：`开始日期不能晚于结束日期。请重新选择日期。`
- 导入成功：`已成功导入 X 条数据，有 Y 条需要核对。`
- 没有货柜：`目前没有可查看的货柜。请从左侧菜单进入“数据导入”，先导入结算单。`

接口返回的技术错误不得直接作为唯一提示展示。界面先显示可理解的中文说明，必要时可在当前页的“查看详细原因”折叠区保留原始错误，供协助人员排查。

## 交互与数据流

- 页面首次进入时加载默认范围的数据。
- 用户修改筛选项只更新表单，不发送查询请求。
- 点击`查看结果`后先校验日期，再一次性提交当前筛选条件。
- 查询期间禁用主要按钮并显示`正在查询`，完成后显示新的当前查看范围。
- 多次快速查询时只采用最后一次请求结果，避免旧结果覆盖新结果。
- 展开和收起只改变当前页面的信息密度，不改变路由。
- 桌面端与移动端使用同一套路由和页面职责，不增加第二套导航层级。

## 视觉与可访问性

- 采用白色和浅灰页面底色、深色正文、绿色主要操作和琥珀色提醒，保持足够对比度。
- 不使用深色主题、渐变、装饰性英文、复杂动效或大面积低对比度文字。
- 页面标题、说明、表单、结果之间保持稳定间距；固定格式区域设置明确的网格和响应式约束。
- 正文在移动端不小于 16 像素；可点击区域至少 44×44 像素。
- 键盘焦点清晰可见，错误区域使用适当的无障碍状态提示。
- 移动端不得横向滚动；筛选项和结果卡片改为单列或两列，文字允许自然换行。
- 图表必须同时提供文字结论或列表，不能要求用户只靠颜色或悬停理解数据。

## 边界

本轮只修改前端页面、组件、样式和必要的前端测试，不修改后端接口、数据库、认证流程或导入规则。后端趋势接口无法提供分等级趋势的问题不在本轮扩展接口解决；页面不得用错误的归一化数据伪装 A、B、C 趋势，可改为展示接口真实提供的每日总销量与总销售额。

## 验收标准

- 侧边栏和移动端菜单均只显示四个确认后的中文菜单名。
- 每个菜单页面都没有跳转到其他菜单的按钮、链接、可点击卡片或标签切换。
- 修改日期和下拉选项不会自动查询，点击`查看结果`后才查询。
- 页面可见内容中没有英文单词或英文装饰标题；仅保留带中文解释的 A、B、C、BC 业务等级代码、用户文件名和接口原始数据。
- 空数据、查询失败、日期错误和导入结果都同时说明当前情况与下一步操作。
- 复杂图表、销售明细、计算说明和来源追溯默认收起。
- 桌面端 1440×900、平板端 768×1024、移动端 375×812 下无内容遮挡或横向滚动，主要操作可清楚识别。
- 前端现有测试、生产构建和后端回归测试通过。
- 实际应用在 `53001` 启动后，由果农按四项核心任务进行体验，再通过视觉伴侣确认最终界面。

## 果农体验任务

邀请果农在不接受操作提示的情况下完成以下任务，并记录是否能独立完成、在哪一步停顿、是否误入其他菜单：

1. 查看全部货柜的总销售额。
2. 比较两个货柜哪个销量更高。
3. 查看一个指定货柜的平均每件售价。
4. 选择一份结算单并确认导入结果。

每项任务完成后只问“你刚才看到的结果是什么意思”和“下一步你会点哪里”，避免诱导答案。若多数体验者在同一位置停顿，应优先修改文案、按钮名称或信息顺序，再进行视觉伴侣复验。

## 验证方式

- 使用前端单元测试验证筛选不会自动查询、主要按钮触发查询、组件不发出跨菜单导航事件。
- 运行前端生产构建检查模板、类型和样式。
- 运行后端回归测试，确认前端改造未伴随接口改动。
- 扫描 Vue 模板中的可见英文文本，并人工核对业务等级代码例外。
- 在桌面、平板和移动端检查四个页面的布局、折叠状态、加载、空数据、错误和成功状态。
- 使用键盘依次操作菜单、筛选、主要按钮与展开控件，确认焦点顺序和焦点样式清楚。
- 在 `53001` 上展示实际应用，并通过视觉伴侣收集最终确认。
