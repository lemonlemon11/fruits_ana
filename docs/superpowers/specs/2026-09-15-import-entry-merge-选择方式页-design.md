# 数据导入与手工录单入口整合（方案 C）设计

日期：2026-09-15
状态：已确认（用户选择方案 C）
适用仓库：`fruits_ana`（业务端）

## 1. 背景

「数据导入」（`/imports`）与「手工录单」（`/entry`）是两条都要保留的录入通路：
前者批量吃批发市场的结算单表格，后者给没有表格、需要现场补录的场景兜底。
现状是两个平行菜单项，业务员要先想「我该进哪个」，也没有地方看到「上次导入结果」和
「没填完的单子」。

本轮把两者整合到**一个菜单入口**，进入后先选录入方式，顺带把最近导入和未完成的手工单
摆在同一个页面上。

## 2. 方案 C 定义（已确认）

菜单只留一项「录单 / 导入」，点进去是「选择录入方式」页：

- 两张方式卡片：
  - 文件导入：批发市场给的结算单表格，批量上传，自动生成结算单与明细 → `/imports`
  - 手工录单：没有表格或需要现场补录时，按模板一项项填，保存后生成结算单 → `/entry`
- 最近导入：最近 3 个导入批次（单号/文件名 + 时间 + 状态胶囊：成功 / 需关注 / 失败），底部入口进 `/imports`
- 未完成的手工单：本地草稿（商号 + 单号 + 明细行数 + 最后编辑时间），按钮「继续录单」→ `/entry?draft=1`

设计源稿：`frontend/dev-preview/import-entry-merge.html`（53001 预览，可切 A/B/C 与桌面/手机）。

## 3. 路由与导航

| 路径 | 页面 | 说明 |
| --- | --- | --- |
| `/entry-hub` | 选择录入方式（新） | 菜单「录单 / 导入」指向这里 |
| `/imports` | 文件导入（不变） | 保留深链与现有页签行为 |
| `/entry` | 手工录单（不变） | 保留深链与详情页「修改录单」跳转 |

- 三个路径共用同一个侧栏高亮项：导航项增加 `matches` 前缀集合，高亮判定改为
  `isNavActive(item, route.path)`。
- 页签仍按路径独立：`/entry-hub` = 「录单 / 导入」、`/imports` = 「文件导入」、
  `/entry` = 「手工录单」（仅作为页签元数据存在，不进侧栏）。
- 「更多」里不再重复出现「手工录单」。

## 4. 权限

- 「文件导入」卡片与最近导入对所有登录用户可见（与现状一致）。
- 「手工录单」卡片与「未完成的手工单」仅当用户拥有 `entry:view` 时渲染
  （`operator` 也可录单，仍由管理端角色授权决定）。
- 无 `entry:view` 的用户停留在 `/entry-hub` 只会看到导入相关区块；直接访问 `/entry`
  仍由路由守卫按现有逻辑退回 `/overview`。

## 5. 草稿机制（未完成的手工单）

本期**不新增后端接口与表结构**，草稿存浏览器 `localStorage`：

- 键：`fruit-entry-draft:v1:<userKey>`，`userKey` 取当前用户 id，避免同机多账号串号。
- 结构：`{ updatedAt, editing, merchantNo, orderNo, salesCount, payload }`，
  `payload` 为完整表单快照（与 `EntryPayload` 同构，便于直接回填）。
- 写入时机：录单页表单变更后防抖 800ms 写入；数据为空时删除草稿。
- 清理时机：保存成功（新建或覆盖修改）后删除；用户在录单页清空内容后删除。
- 读取时机：`/entry?draft=1` 时优先回填草稿（保持「修改中」语义），否则维持现有
  `?merchant_no=` 读取服务端逻辑。
- 退出登录不主动清草稿（同一账号下次登录仍可续填）。

## 6. 非目标

- 不做服务端草稿、多草稿列表、跨设备续填。
- 不改 `EntryView` 的字段、校验规则、导出与冲突覆盖语义。
- 不在 `ImportView` 内新增跳转入口（保持「页面内部不跨菜单跳转」的既有约定）。

## 7. 验收标准

1. 侧栏 / 移动端底部导航只有一项「录单 / 导入」，点击进入 `/entry-hub`；
   在该页与 `/imports`、`/entry` 上导航项保持高亮。
2. hub 页两张卡片可分别进入文件导入与手工录单（无 `entry:view` 时只有导入卡片）。
3. 最近导入按时间倒序展示 3 条，状态胶囊与批次状态一致；空数据有兜底文案。
4. 录单页填一半切走，hub 页出现「未完成的手工单」，点「继续录单」能恢复未保存内容；
   保存成功后该条目消失。
5. 桌面与 390px 移动端均无横向溢出，页面不出现多段横向滚动。
6. 既有验证基线不回退：后端 `pytest`、前端 `test` / `typecheck` / `build` 全绿。
