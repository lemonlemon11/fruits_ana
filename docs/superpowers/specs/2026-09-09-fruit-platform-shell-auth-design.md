# 果级经营台壳层与认证改版设计

## 目标

在保留现有水果销售分析业务页面和接口的前提下，重做应用级壳层并补齐最小可用认证能力：

- 用固定 Header 统一承载品牌、当前页面、主题切换、菜单控制和用户入口。
- 让左侧菜单支持展开/收起，并把内容区改成更紧凑、首屏优先的工作台布局。
- 新增独立的登录页和注册页，并实现真实的注册、登录、登出和登录态保护。

## 范围

### 本期包含

- 桌面端固定 Header，移动端保留固定移动 Header。
- 侧栏展开态约 228px、收起态约 76px；收起时保留可识别的图标/编号和 aria-label。
- 现有三套主题继续保留：自然经营、深色指挥台、高对比；主题入口移动到 Header。
- 页面间距、卡片内边距、筛选区域和主内容滚动策略压缩，减少不必要的纵向滚动。
- `/login` 登录页面。
- `/register` 注册页面。
- SQLite 用户表。
- Argon2 密码哈希。
- HttpOnly、SameSite=Lax 会话 Cookie。
- 注册、登录、当前用户、登出 API。
- 前端认证状态、路由守卫和登录后跳转。
- 业务页面要求登录；认证页面在已登录时回到总览。
- 后端认证单元/API 测试和前端认证/路由行为测试。

### 本期不包含

- 第三方 OAuth、短信验证码、邮箱验证。
- 找回密码、修改密码、双因素认证。
- 多角色权限矩阵、组织/租户隔离和后台用户管理。
- 生产级分布式会话存储、Redis 和跨服务 SSO。
- 业务分析接口的指标重构。

## 产品流程

### 未登录用户

1. 访问 `/` 或任一业务路由。
2. 前端路由守卫请求当前会话。
3. 没有有效会话时跳转 `/login`，并保留原目标路径。
4. 登录成功后回到原目标路径；没有目标路径时回到 `/overview`。

### 注册用户

1. 在 `/register` 输入显示名称、邮箱和密码两次。
2. 前端先做格式、长度和一致性校验。
3. 后端再次校验，并以 Argon2 哈希保存密码。
4. 邮箱已存在时返回通用错误，不暴露额外账户信息。
5. 注册成功后建立会话并进入 `/overview`。

### 已登录用户

- Header 显示当前用户和退出入口。
- 主题切换在 Header 中完成，并继续使用 localStorage 记忆选择。
- 点击退出后清除服务端会话和前端认证状态，回到 `/login`。

## UI 设计

### 应用壳层

- Header 高度约 56px，`position: sticky` 或固定主容器顶部，始终可见。
- Header 和内容使用同一组主题 Token，避免主题切换后出现孤立颜色。
- 桌面端只让主内容区滚动；侧栏和 Header 保持可见。
- 业务页保留现有信息层级，但默认垂直间距降为 8/12/16px 三档。
- 首屏优先显示页面标题、筛选器、关键 KPI 和一张主要图表；次要来源/追溯信息使用折叠区域。
- 移动端使用抽屉式导航；Header 保留菜单按钮、当前页面、主题选择和用户入口。

### 登录页

- 使用与业务壳层一致的品牌和主题 Token，但不显示业务侧栏。
- 桌面端采用左右分栏：左侧是产品定位、数据治理与分析价值，右侧是登录卡片。
- 登录卡片字段：邮箱、密码；提供“登录”和“注册账号”入口。
- 错误显示在对应字段附近或表单顶部，提交中显示明确 loading 状态。
- 不使用占位符替代字段 label；支持键盘提交、焦点可见和移动端单列布局。

### 注册页

- 延续登录页骨架，视觉上明确当前处于“创建账号”流程。
- 字段：显示名称、邮箱、密码、确认密码。
- 提供密码长度/一致性提示；邮箱重复、服务错误和字段错误使用可理解的中文反馈。
- 提供“返回登录”入口；注册成功后进入总览。

## 认证接口契约

### `POST /api/auth/register`

请求：

```json
{
  "display_name": "张三",
  "email": "user@example.com",
  "password": "至少 8 位"
}
```

成功：`201`

```json
{
  "user": {"id": "...", "display_name": "张三", "email": "user@example.com"}
}
```

### `POST /api/auth/login`

请求：

```json
{
  "email": "user@example.com",
  "password": "..."
}
```

成功：`200`，设置 HttpOnly 会话 Cookie，响应体返回非敏感用户信息。

失败：统一返回 `401`，不区分“邮箱不存在”和“密码错误”。

### `GET /api/auth/me`

- 有效会话返回当前用户信息。
- 无效或缺失会话返回 `401`。

### `POST /api/auth/logout`

- 使当前会话失效并清除 Cookie。
- 重复退出也应安全返回 `204` 或 `200`。

## 数据与安全设计

用户表至少包含：`id`、`display_name`、`email`、`password_hash`、`created_at`、`last_login_at`、`is_active`。

- 邮箱保存为规范化的小写值，并建立唯一索引。
- 密码只保存 Argon2 哈希，绝不保存明文或可逆加密值。
- 会话 Cookie 使用 `HttpOnly`、`SameSite=Lax`，生产 HTTPS 下设置 `Secure`。
- 会话随机值只保存哈希或可撤销的服务端会话记录，避免把用户信息直接编码进 Cookie。
- 登录和注册错误不暴露账户是否存在。
- 前端不把密码写入 localStorage、sessionStorage 或 URL。
- 认证接口保留后续加入限流和账户锁定的扩展点；本期至少覆盖重复邮箱、弱密码、错误密码和失效会话。

## 验收标准

### 壳层

- [ ] 桌面端 Header 始终固定/可见，内容滚动不会遮挡 Header。
- [ ] 主题切换只在 Header 提供，三套主题均能切换并刷新后保持。
- [ ] 侧栏可展开/收起，收起后仍能通过图标、编号、tooltip 或 aria-label 使用导航。
- [ ] 主内容默认使用紧凑间距；总览首屏能同时看到标题、筛选器、核心 KPI 和主要图表入口。
- [ ] 移动端不产生横向滚动，菜单、主题和用户入口均可操作。
- [ ] 键盘焦点、跳过链接和 reduced-motion 行为不回归。

### 认证

- [ ] 未登录访问任一业务路由会跳转 `/login`。
- [ ] `/login` 和 `/register` 是独立可访问页面，不依赖业务侧栏。
- [ ] 注册成功创建用户并建立登录态。
- [ ] 重复邮箱、非法邮箱、短密码和确认密码不一致有明确错误。
- [ ] 登录成功进入原目标页或 `/overview`。
- [ ] 错误密码返回统一认证错误，不泄露邮箱是否存在。
- [ ] 刷新页面后有效会话仍可恢复；退出后业务路由再次要求登录。
- [ ] 密码不会出现在响应体、日志、URL 或浏览器存储中。

## 测试策略

- 后端模型/API：注册成功、重复邮箱、登录成功、错误密码、当前用户、退出和失效会话。
- 前端路由/认证状态：未登录重定向、登录回跳、已登录访问认证页、登出清理。
- 前端壳层：Header 固定结构、主题切换、侧栏收起、移动端菜单。
- 生产构建和现有后端全量测试必须继续通过。
- 浏览器验收至少覆盖桌面宽屏、窄桌面和移动视口；重点检查滚动容器、Header 遮挡、登录表单错误和退出流程。

## 风险与控制

| 风险 | 控制措施 |
| --- | --- |
| 认证改造影响现有分析 API | 认证路由独立注册，先补测试，再逐步给前端业务路由加守卫 |
| SQLite 并发会话能力有限 | 首版仅支持单体部署，抽象会话接口，后续可替换 Redis |
| Header/侧栏固定后内容被遮挡 | 统一计算内容 top inset，并做不同视口浏览器验收 |
| 紧凑布局造成信息密度过高 | 保留标题/标签/焦点状态，次要信息折叠，不把正文缩到 12px 以下 |
| 主题切换造成低对比度 | 继续使用语义 Token，分别检查浅色、深色和高对比主题 |
