# 水果等级销售经营分析平台设计

日期：2026-09-08  
状态：待用户审核

## 1. 目标与使用者

系统面向管理者/老板，核心任务是查看不同水果等级的销售情况，支持两类场景：

1. 销售进行中按天跟踪等级销量与均价变化。
2. 每个货柜销售结束后复盘等级结构、价格和销售结果。

回款不是首期核心；结算单中的应付金额、售后、费用和清关税费只作为单柜结果的辅助解释信息。

## 2. 已确认范围

### 首期包含

- 批量上传 Excel/CSV 结算单。
- 解析并标准化货柜、销售日期、等级、数量、单价、金额、售后、费用、清关税费等字段。
- 等级只按 A/B/C 展示；BC 自动归入 C，并显示为“C 果（含 BC）”。
- 全局总览与单柜诊断两种视图并列，并支持场景切换。
- 日期范围和货柜筛选。
- 等级销量、销售额、加权均价、销量占比。
- 日量价趋势、货柜间等级结构与均价对比。
- 原始明细追溯、导入批次记录、数据质量提示、报表导出。

### 明确不在首期

- 利润测算、采购成本录入和成本分摊。
- 实际回款登记与回款状态管理。
- 外部行情自动采集。
- 复杂的多角色权限体系。

## 3. 用户流程

1. 管理者上传一个或多个结算单文件。
2. 系统保留原始文件，解析文件并执行字段、等级、日期、金额校验。
3. 系统展示导入结果：成功记录数、警告数、失败数和错误明细。
4. 管理者进入全局总览，按日期或货柜筛选 A/B/C 销售表现。
5. 管理者切换到单柜诊断，查看该柜的等级结构、日量价趋势和与全局同期的差异。
6. 需要核对时，从汇总指标下钻到标准化销售明细，再追溯原始结算单。
7. 管理者导出当前筛选范围的复盘报表。

## 4. 数据模型

### 原始文件与导入批次

- `import_batch`：批次 ID、文件名、导入时间、状态、成功/警告/失败数量、错误摘要。
- `source_file`：原始文件路径或对象引用、文件哈希、来源批次、保存时间。

### 销售明细事实

- `sale_record_id`：稳定明细 ID。
- `import_batch_id`、`source_file_id`：追溯来源。
- `container_id`、货柜号、柜名。
- `sale_date`：销售日期。
- `fruit_type`：品种，当前为榴莲，保留扩展能力。
- `grade_raw`：原始等级文本。
- `grade`：标准等级 A/B/C，BC 映射为 C。
- `spec_raw`：原始品种规格文本，首期保存但不作为主看板维度。
- `quantity`、`unit_price`、`amount`。
- `remark`：原始备注或状态文本。
- `sales_region`：销售地区，当前预留为空。

### 货柜结算摘要

- 货柜销售金额、售后金额、货款/汇总金额。
- 费用明细与费用合计。
- 清关税费。
- 应付结算总额。

## 5. 指标口径

- 销量 = 当前筛选范围内销售数量之和。
- 销售额 = 当前筛选范围内销售金额之和。
- 加权均价 = 销售额 ÷ 销量；销量为 0 时显示“暂无数据”。
- 销量占比 = 该等级销量 ÷ 当前筛选范围总销量；总销量为 0 时显示“暂无数据”。
- BC 等级统一计入 C；原始等级仍保留以便核对。
- 日期趋势按销售日期聚合，不按导入日期聚合。

## 6. 页面与功能

### 6.1 全局等级总览

- 筛选：日期范围、货柜、品种（预留）。
- A/B/C 指标：销量、销售额、加权均价、销量占比。
- 图表：每日销量与均价趋势；各货柜等级结构和等级均价对比。
- 支持点击等级或货柜进入对应明细/单柜诊断。

### 6.2 单柜经营诊断

- 展示选定货柜的 A/B/C 指标和销售周期。
- 展示该柜按销售日期的量价变化。
- 提供全局同期均价或结构作为对比基线。
- 展示售后、费用、清关税费、结算金额等辅助信息。
- 支持下钻到该柜标准化销售明细与原始来源。

### 6.3 导入与数据质量

- 批量上传 Excel/CSV，记录导入批次和文件哈希。
- 检查缺少日期、数量或金额；未知等级；金额不一致；重复导入。
- 提供错误明细下载；首期由管理者修正文件后重新导入。
- 导入失败不应污染已成功入库的数据。

### 6.4 导出

- 导出当前筛选范围的等级汇总、趋势数据和单柜复盘明细。
- 导出内容注明数据范围、生成时间和等级映射规则。

## 7. 异常提示

分为两类：

- 数据质量异常：字段缺失、等级无法识别、金额校验失败、重复导入。
- 经营异常：某等级均价较同期明显下降、某货柜等级结构明显偏离整体、某日销量或金额异常。

首期只提示并提供明细，不自动改写业务数据；异常阈值应配置化，初始值在试运行中校准。

## 8. 权限与非功能要求

- 首期只有管理者角色：可导入、查看、确认异常、导出。
- 所有汇总指标必须可追溯到标准化明细和原始文件。
- 重复导入应可识别，处理过程可重试且不产生重复事实记录。
- 解析规则和等级映射应集中管理，避免不同报表使用不同口径。
- 看板优先保证最近导入数据可用；大文件解析应异步化并显示进度。

## 9. 待办与后续版本

### 明确待办：详情表格接入

用户后续会提供包含数据详情的表格文件。收到后需要：

1. 识别其主键、货柜/日期关联键与新增字段。
2. 与销售明细事实建立稳定关联，避免重复计算。
3. 评估规格、品质状态、销售地区等维度是否进入看板。
4. 补充导入校验、指标口径和报表需求。

### 二期候选

- 成本数据导入与利润测算。
- 果民采购成本、国内物流和报关费用分摊。
- 销售地区维度分析。
- 价格/利润预警。
- 多用户角色与审计。
