# 结算单单号身份与覆盖导入设计

## 背景

当前销售分析以 `container_id` 作为对比、详情和结算摘要的分组键。柜号会重复，
例如 `637结算单（宝贝003）` 与 `640结算单（宝贝L004）` 的柜号均为
`CBHU2970762`，导致两个独立结算单被合并。

Excel 中真正的业务唯一标识是“单号”字段，例如 `宝贝003`、`宝贝L004`。
“商号”字段中的 `637`、`640` 不作为唯一标识。

## 目标

- 使用单号 `settlement_no` 作为业务唯一键。
- 保留数据库整数 `id` 作为内部主键和外键目标。
- 允许不同单号使用相同柜号，并在分析中保持独立。
- 重复单号导入前询问用户是否覆盖。
- 覆盖失败时保留原有数据。
- 为导入页补充拖放文件能力。

## 数据模型

在 `import_batch` 增加非空字段 `settlement_no`，并建立唯一索引。
`sale_record`、`container_summary` 和 `data_issue` 继续通过 `import_batch_id`
关联导入批次，不重复保存单号。

`container_id` 保留为可重复的业务属性。分析查询通过关联 `import_batch`，按
`settlement_no` 筛选和分组。

## 单号解析

- Excel：从表头上方标记为“单号”的元数据单元格读取，保留字符串形式。
- CSV：支持 `settlement_no`、`order_no`、`单号` 和 `结算单号` 列。
- 单号会去除首尾空白，但不改变大小写或内部字符。
- 缺少单号时拒绝该文件，不创建导入批次。

## 重复与覆盖

默认上传不覆盖。服务端解析到已存在的 `settlement_no` 时返回 `conflict`，响应包含
单号和既有批次信息，不修改数据库。

前端收到冲突后显示确认界面：

- 取消：保留原数据，不再次提交。
- 覆盖：使用显式覆盖参数重新上传该文件。

一次选择多个文件时，每个文件独立处理。新单号正常导入；冲突文件保留在待确认
列表中，并按文件分别取消或覆盖，单个冲突不回滚已经成功导入的其他文件。

覆盖流程先完成文件解析和校验，再在一个数据库事务内替换旧批次及其销售记录、
摘要、问题和来源引用。事务提交后才清理不再使用的旧文件；解析或提交失败时回滚，
旧数据保持可用。

完全相同的文件也按单号冲突处理，由用户决定是否覆盖。

## API 与分析语义

- 导入响应增加 `settlement_no`，并支持 `conflict` 状态。
- 分析筛选参数从 `container_id` 调整为 `settlement_no`。
- 对比结果以 `settlement_no` 唯一标识，并同时返回 `container_id`。
- 详情接口按单号查询；柜号作为详情属性展示。
- 导出接口按单号导出结算单数据。
- 总览仍汇总当前筛选范围内的所有结算单。

前端对比、详情和链接使用单号传递身份，界面以单号为主标签、柜号为辅助信息。

## 现有数据迁移

迁移脚本执行以下步骤：

1. 备份当前 MySQL 数据库。
2. 为 `import_batch` 添加可空 `settlement_no`。
3. 从每个 `source_file.storage_path` 指向的原始文件读取“单号”并回填。
4. 验证没有缺失或重复单号。
5. 将字段改为非空并创建唯一索引。

当前 4 个批次应回填为 `宝贝003`、`宝贝01`、`宝贝02`、`宝贝L004`。
迁移脚本必须可重复检查；发现异常时停止，不删除或覆盖业务数据。

## 导入交互

现有文件选择面板同时作为拖放区域。拖入时显示明确高亮，放下后进入与点击选择
相同的待导入队列，仍需点击“开始导入”。格式和大小校验复用现有逻辑。

## 验证

- 解析测试：Excel/CSV 单号、缺失单号。
- 模型测试：单号唯一约束。
- 导入测试：新单号、冲突取消、确认覆盖、覆盖失败回滚。
- 分析测试：相同柜号的不同单号在对比和详情中独立。
- 迁移测试：回填成功、缺失/重复时停止、重复执行安全。
- 前端测试：身份字段归一化、冲突确认、拖放选择。
- 完整后端测试、前端测试与生产构建。

## 边界

- 不把“商号”作为身份字段。
- 不移除现有整数主键。
- 不实现导入版本历史；覆盖后只保留当前有效版本及最新来源文件。
- 不修改认证与用户权限模型。
