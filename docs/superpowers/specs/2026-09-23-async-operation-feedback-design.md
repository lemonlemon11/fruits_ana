# 异步操作等待反馈设计

## 目标

为导出、排序、自动查询、录单保存、导入复核和品牌对比选择统一补充及时、可感知、可防重复的等待反馈，避免用户因页面看似无响应而连续点击。

## 设计原则

- 反馈在操作发生后立即出现，耗时未知时使用不确定进度动画，不显示虚假百分比。
- 只锁定当前操作相关控件；排序和对比更新尽量保留旧内容，避免整页闪烁。
- 统一使用按钮文字、局部状态条、`aria-busy` / `aria-live` 表达状态。
- 不改变后端接口、业务口径、筛选逻辑和导出文件内容。

## 方案

### 文件下载

新增前端下载工具，通过带 Cookie 的 `fetch` 获取 Blob，解析 `Content-Disposition` 文件名并触发浏览器保存。页面按导出项维护 busy key：列表导出、每行 Excel/PDF、手工录单模板、问题明细 CSV 相互独立；同一项执行期间禁止重复点击，成功或失败后给出提示。

### 排序和自动查询

`DataTable` 增加 `sortBusy`，排序时保留现有行，在表格顶部显示“正在排序”，禁用排序表头并设置 `aria-busy`。`SearchableSelect` 增加 `loading`，传递给 Element Plus 并在请求期间禁用控件。

### 保存与提交

手工录单将自动暂存、手动暂存和正式保存区分状态；手动暂存失败不能再显示成功提示。导入复核使用操作类型区分切换文件、还原、提交前保存和正式提交，并在按钮和局部状态区显示对应文案。

### 品牌对比

应用结算单选择后保留旧结果并显示“正在更新对比结果”，更新期间禁止再次应用、清空或移除选择。

## 错误处理

- 下载错误优先读取后端 JSON `detail`，否则使用 HTTP 状态或通用文案。
- 查询、排序继续沿用现有 AbortController 和 request version，只有最新请求可以结束 busy 状态。
- 暂存失败显示明确提示，但不阻断用户继续录单。

## 验证

- 新增下载工具单测，覆盖文件名解析、Cookie 请求和错误响应。
- 扩展现有源码契约测试，覆盖导出、排序、下拉、保存、复核和对比 busy 状态。
- 运行前端全量测试、类型检查和构建。
