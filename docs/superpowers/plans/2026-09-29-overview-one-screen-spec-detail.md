## 一、需求背景（老板视角）

老板是水果物流/供应链公司的一级销售单位（ToB），只有结算单可用：结算单记录来货数据、
各等级水果销售（单价/数量/备注）、运输损耗费用与清关入关费用，得出应收款。销售总览
（`/overview`「卖得怎么样」）需要：

1. 快速获取并总结**近期单据信息**；
2. 通过**各等级（及规格级）均价**判断后续定价方式；
3. **一屏看完**（默认状态）；
4. 查看「规格件数与均价」时，点击**查看明细**在页面内展开详情列表，展示
   **各等级各规格果**的销售情况。

## 二、已确认的设计决策（用户逐项拍板）

| 决策点 | 结论 |
| --- | --- |
| 应收款是否进总览 | **不进**。纯销售口径（总柜数/总件数/销售金额/每件均价），零后端改动，不新增 ADR，符合 AGENTS.md「回款/费用/清关只用于单柜经营结果」 |
| 一屏排版策略 | **双栏紧凑网格**（方案 1 修正版）：不做 A/B/C 大等级总均价卡，一屏内直接展示**规格级**数据（如「A果 3头·14kg」的占比+均价），按等级分组、含等级小计行 |
| 近期单据总结形态 | **KPI 数字带 + 覆盖范围小注**（张数、覆盖起止、最新销售日期），不另加最近结算单列表 |
| 查看明细展开形式 | **页内展开（手风琴）**：默认折叠保持一屏；点「查看明细」在卡片下方全宽展开现有 7 列规格明细长表，再点「收起明细」折叠。不跳转、不用抽屉 |
