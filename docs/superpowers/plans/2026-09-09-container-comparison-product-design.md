# 不同货柜数据对比：产品设计方案

日期：2026-09-09  
状态：可进入产品确认与研发拆解  
适用范围：水果等级销售经营分析平台首期增强

## 1. 需求目标

围绕“做一个不同货柜的数据对比”，让管理者在同一筛选范围内快速回答三个问题：

1. 哪些货柜贡献了主要销量和销售额？
2. 各货柜的 A/B/C 等级结构、加权均价有何差异？
3. 某个货柜表现异常时，能否无损衔接到单柜诊断并追溯原因？

首期重点是经营表现比较，不扩展利润、成本、回款、客户、渠道等尚无稳定数据来源的维度。`BC` 继续统一归入 C，并在界面显示为“C 果（含 BC）”。

## 2. 用户与使用场景

### 2.1 主要用户

- 管理者 / 老板：先看整体和排名，再定位需要关注的货柜。
- 业务复盘人员：比较等级结构和价格表现，进入单柜核对日期、明细、售后与费用背景。

### 2.2 核心场景

- **日常跟踪**：在最近一段销售日期内比较所有货柜，关注销售额、销量、均价和结构变化。
- **货柜复盘**：从横向对比中选择一个货柜，查看其相对同期其他货柜的差异和原始明细。
- **异常核对**：看到低均价、结构偏离或数据质量提示后，进入单柜诊断和来源记录。

## 3. 已有能力与缺口

### 3.1 可直接复用的能力

- `GET /api/analytics/overview`：返回筛选范围总量、等级汇总、异常和数据质量数量。
- `GET /api/analytics/container-comparison`：按货柜返回 `total` 与 A/B/C `grades` 指标。
- `GET /api/analytics/containers/{container_id}`：返回单柜汇总、等级指标、趋势、销售周期、结算辅助信息、明细和异常。
- 前端已有 `ContainerComparison.vue`，支持按销售额、销量、加权均价排序，并可点击货柜进入单柜诊断。
- 前端已有 `ComparisonPanel.vue`，可展示整体等级结构以及当前单柜对整体销量/销售额的贡献。
- 后端汇总统一复用销售明细事实，销量、销售额、加权均价、数量占比已有稳定计算逻辑。

### 3.2 本需求必须补齐的缺口

- 货柜横向对比接口目前未稳定返回货柜名称、销售周期、明细数量等可信度信息；前端只能回退显示货柜 ID。
- 当前单柜“同期整体基线”包含当前柜，容易稀释差异；对外文案也未明确基线是否排除当前柜。
- “等级结构占比”“单柜对整体贡献率”“单柜对某等级贡献率”容易混称，需要统一名称和公式。
- 当前横向对比未直接显示单柜占整体销量/销售额的贡献率，也未展示绝对差、相对差和百分点差。
- 样本不足时后端会停止生成部分异常，但界面未解释“未触发异常”是否因为样本不足。
- 移动端现有对比组件以信息块为主，但完整等级对比区仍可能依赖横向滚动，不符合 375px 无横向溢出的验收要求。

## 4. 推荐产品方案

采用“**全量货柜横向排名 + 点击进入单柜诊断**”的两层模式：

1. 全局汇总页展示所有符合筛选条件的货柜，每行一个货柜；用统一列比较总量、贡献率、等级结构和等级均价。
2. 点击货柜后进入单柜诊断，保留日期筛选，用“当前柜 vs 同期其他货柜”作为默认基线。
3. 首期不增加复杂的多选并排工作台。管理者可通过排序、货柜搜索和逐柜下钻完成主要决策，避免移动端多列并排和接口复杂度迅速上升。

备选方案及取舍：

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 全量货柜列表 + 单柜下钻 | 兼容现有接口和页面；适合货柜数量较多；移动端可卡片化 | 两个具体货柜的逐项比较需要来回切换 | **首期推荐** |
| 选择 2–3 个货柜并排比较 | 适合精细复盘 | 多选状态、窄屏布局和接口返回更复杂 | 二期候选 |
| 只展示 Top/Bottom 榜单 | 首屏简单 | 容易遗漏中部货柜，等级结构信息不足 | 不作为主方案 |

## 5. 比较对象与维度

### 5.1 比较对象

- 主比较对象：`container_id`，展示名称优先使用 `container_name`，名称为空时回退为货柜 ID。
- 比较集合：当前日期范围内至少有一条有效销售明细的货柜。
- 同一货柜在不同导入批次中的有效明细按销售日期和货柜 ID 汇总；重复文件由导入层去重，不在分析层二次去重。
- 不把没有销售明细、只有结算摘要的货柜纳入销量排名；可在空态中单独提示“有结算摘要但无销售明细”。

### 5.2 首期比较维度

| 维度 | 用途 | 规则 |
| --- | --- | --- |
| 货柜 | 横向排名、选择诊断对象 | 使用稳定 `container_id` |
| 销售日期 | 限定同期范围、趋势和基线 | 按 `sale_date`，不是导入时间 |
| 等级 | 比较 A/B/C 结构和等级均价 | BC 归入 C，原始文本仅在明细追溯 |
| 总体 | 比较货柜总销量、总销售额、整体均价 | 汇总该柜筛选范围内全部等级 |

首期不提供等级过滤器。等级在同一货柜内必须完整展示，避免用户筛选单一等级后误把其占比理解为完整等级结构。`fruit_type`、`sales_region`、规格等维度在详情表格接入并确认口径后再扩展。

## 6. 指标与计算口径

所有分子和分母必须使用同一销售日期范围、同一有效销售明细集合。销售金额以标准化销售明细中的 `amount` 为准，不使用结算摘要覆盖。

| 指标 | 公式 | 展示与边界 |
| --- | --- | --- |
| 销量 | `Σ quantity` | 当前格式最多 1 位小数；数量单位需业务确认 |
| 销售额 | `Σ amount` | 默认人民币，列表取整展示，详情可保留更高精度 |
| 加权均价 | `Σ amount ÷ Σ quantity` | 销量为 0 时为 `null`，显示“暂无数据”，不得显示 0 |
| 等级结构占比 | `本柜该等级销量 ÷ 本柜总销量` | 用于 A/B/C 结构条；总销量为 0 时显示“暂无数据” |
| 单柜销量贡献率 | `本柜总销量 ÷ 当前比较集合总销量` | 回答该柜对整体销量贡献多少 |
| 单柜销售额贡献率 | `本柜总销售额 ÷ 当前比较集合总销售额` | 回答该柜对整体销售额贡献多少 |
| 单柜等级销量贡献率 | `本柜该等级销量 ÷ 当前比较集合该等级总销量` | 只在单柜诊断或展开详情展示 |
| 单柜等级销售额贡献率 | `本柜该等级销售额 ÷ 当前比较集合该等级总销售额` | 只在单柜诊断或展开详情展示 |
| 均价绝对差 | `本柜加权均价 - 基线加权均价` | 单位与均价一致，如 `-2.40 元/单位` |
| 均价相对差 | `(本柜均价 ÷ 基线均价) - 1` | 基线为 0 或空时不计算 |
| 等级结构差 | `本柜等级占比 - 基线等级占比` | 必须用“百分点”，如 `+6.8 个百分点` |

术语必须严格区分：

- “结构占比”表示某等级在**本柜内部**的构成。
- “贡献率”表示某货柜占**当前比较集合**的份额。
- “差值”表示当前柜与基线的绝对或相对差异。

百分比统一显示 1 位小数；均价显示 2 位小数；同一页面不得混用“百分比”和“百分点”。金额、数量和均价的最终单位需要在上线前确认并写入标题、表头或 tooltip。

## 7. 对比基线规则

### 7.1 全局汇总页

比较集合默认为日期筛选内的全部有效货柜。总销量、总销售额、等级总量和各货柜贡献率都以该集合为分母。

### 7.2 单柜诊断页

默认基线推荐为“**同期其他货柜**”：相同日期范围、排除当前柜后剩余货柜的汇总结果。原因是包含当前柜会使差异向 0 收敛，尤其在当前柜贡献率较高时不利于诊断。

页面标题必须明确显示：

> 对比基线：YYYY-MM-DD 至 YYYY-MM-DD 的其他 N 个货柜（不含当前柜）

当没有其他货柜时，不计算差值，不显示绿/红优劣判断，改为“当前范围只有 1 个货柜，无法形成横向基线”。

如业务最终要求与“含当前柜整体”比较，必须更改标题和公式，不能只改后端计算而保留模糊的“同期整体”文案。

## 8. 页面信息架构与交互

### 8.1 全局汇总页

从上到下建议为：

1. **筛选条**：开始日期、结束日期、货柜搜索/筛选、刷新；标题下方始终显示当前范围。
2. **全局汇总**：总销量、总销售额、整体加权均价、有效货柜数。
3. **货柜横向对比**：本需求的主区域。
4. **趋势与异常**：用于解释排名变化，不抢占对比主区的第一视觉层级。

货柜横向对比每行至少显示：

- 货柜名称 / ID、销售周期、有效明细数。
- 总销量及销量贡献率。
- 总销售额及销售额贡献率。
- 整体加权均价。
- A/B/C 等级结构条与各等级占比。
- A/B/C 等级加权均价。
- 数据可信度/经营提示。
- “查看诊断”入口。

建议默认只突出总指标和结构；等级详细数值可在桌面端直接展示，在窄屏通过“展开等级明细”显示，避免首屏信息过载。

### 8.2 单柜诊断页

从横向对比进入后：

- 继承开始日期、结束日期和场景，URL 至少保留 `container_id`，建议同时保留日期参数，支持刷新和分享。
- 顶部显示“返回货柜对比”，返回后恢复原筛选与排序。
- 先展示当前柜总量和对整体贡献，再展示 A/B/C 结构、均价及与其他货柜基线的差值。
- 异常卡片必须说明当前值、基线值、阈值、样本状态，并可继续下钻到标准化明细。
- 售后、费用、清关、应付结算保持为辅助信息，不加入首期货柜经营排名。

### 8.3 联动规则

- 点击货柜行只切换诊断对象，不改变日期范围。
- 在单柜下拉框切换货柜时，基线重新排除新选中的当前柜。
- 对比列表中的数字、单柜摘要中的数字与导出结果必须来自同一指标服务；不允许前端分别求和造成口径漂移。
- 如果全局页选择“单一货柜”筛选，对比区应明确进入“筛选结果”状态，不再显示横向排名。产品更推荐将货柜筛选改为搜索/定位而不是改变全局分母，最终行为见待确认问题。

## 9. 排序与筛选

### 9.1 默认排序

- 默认：销售额从高到低，符合管理者先找主要贡献货柜的习惯。
- 可选：销量、销售额、加权均价、销量贡献率、销售额贡献率。
- 可选方向：升序 / 降序，默认降序。
- 相同值时按 `container_id` 自然升序；空值永远排在末尾。
- 当前排序字段在表头和移动端排序控件中保持可见。

异常优先不作为默认排序，因为低样本异常可能抢占首屏。可提供独立的“仅看需关注”筛选。

### 9.2 筛选规则

- 日期范围：支持开始日期、结束日期；开始日期晚于结束日期时前端阻止提交，后端继续返回 422。
- 货柜：支持按名称或 ID 搜索定位；是否改变比较集合和贡献率分母必须采用一种稳定规则。
- 经营状态：首期可选“全部 / 仅看需关注 / 仅看数据不足”，取决于接口是否返回状态字段。
- 等级：首期不作为过滤条件，只作为展示和排序维度。
- 清空筛选后恢复全部有效销售日期、全部货柜和默认排序。

推荐将“货柜搜索”设计为仅定位/缩小可见行，但贡献率分母仍保持当前日期范围内全部货柜；若产品选择真正过滤，页面必须显示“贡献率已按筛选后的 X 个货柜重算”。

## 10. 手机端交互（375px 基线）

- 筛选条改为单列，主按钮和可点击区域高度不小于 44px。
- 对比表转为纵向货柜卡片，不使用必须横向拖动才能理解的宽表。
- 卡片默认层级：货柜名称 → 销售额 / 贡献率 → 销量 / 贡献率 → 均价 → A/B/C 结构条。
- “展开等级明细”展示各等级销量、占比、销售额、均价；同一时间只需展开一个货柜，减少页面长度。
- 排序使用页面顶部的下拉或底部弹层，明确字段与方向；切换后列表回到顶部并保持筛选条件。
- 点击卡片主体或“查看诊断”进入单柜；返回后恢复滚动位置、筛选和排序。
- 超长货柜名称允许两行，ID 保持可见；金额不得挤压或覆盖操作入口。
- 加载使用卡片骨架；接口失败在列表区域显示重试，不清空用户已选筛选条件。
- 不以纯红绿表示优劣，差值同时使用 `+/-`、文案和单位，满足可访问性要求。

## 11. 空态、异常与样本不足

| 状态 | 展示规则 | 禁止行为 |
| --- | --- | --- |
| 无任何销售数据 | “暂无货柜销售数据”，提供前往导入入口 | 不显示全 0 排名 |
| 当前日期无数据 | 显示筛选日期和“调整日期范围”操作 | 不沿用上一筛选结果 |
| 只有 1 个货柜 | 展示该柜自身指标；提示无法横向比较 | 不生成伪基线和优劣色 |
| 某柜销量为 0 | 均价、结构占比显示“暂无数据” | 不显示均价 0、占比 0% 或 100% |
| 某等级无销量 | 该等级销量/金额可显示 0，均价显示“暂无数据” | 不用 0 元表示无均价 |
| 接口失败 | 区分失败与空数据，保留筛选并提供重试 | 不把失败渲染为空榜单 |
| 存在数据质量提示 | 显示提示数量并可进入导入问题明细 | 不静默忽略问题记录 |
| 样本不足 | 展示原始指标，标记“样本不足，不做异常判断” | 不用绿色表示“表现正常” |

样本规则应与现有后端阈值保持一致：

- 横向经营异常至少需要 2 个货柜；少于 2 个货柜时不生成均价和结构偏离异常。
- 日销量异常至少需要 3 个有效销售日期；少于 3 天时只展示趋势，不判断异常。
- 首期尚无明确的“最少明细条数/最少销量”阈值；在业务确认前，不基于主观阈值给小样本柜打好坏标签。建议接口补充 `record_count` 和 `valid_sale_day_count`，用于解释样本状态。

## 12. 建议接口契约

### 12.1 横向对比接口

继续使用：

```http
GET /api/analytics/container-comparison?start_date=YYYY-MM-DD&end_date=YYYY-MM-DD
```

每个货柜建议稳定返回：

```json
{
  "container_id": "C1",
  "container_name": "625柜",
  "sales_period": {
    "start_date": "2026-01-01",
    "end_date": "2026-01-10"
  },
  "record_count": 42,
  "valid_sale_day_count": 8,
  "total": {
    "sales_quantity": 120.0,
    "sales_amount": 3600.0,
    "weighted_avg_price": 30.0,
    "quantity_contribution": 0.25,
    "amount_contribution": 0.30
  },
  "grades": [
    {
      "grade": "A",
      "sales_quantity": 50.0,
      "sales_amount": 1750.0,
      "weighted_avg_price": 35.0,
      "quantity_share": 0.4167,
      "quantity_contribution": 0.28,
      "amount_contribution": 0.32
    }
  ],
  "sample_status": "sufficient",
  "attention_count": 1
}
```

如暂不由后端返回贡献率，前端只能在拿到完整比较集合时计算；但基线、异常、导出仍应由后端统一计算。为了避免分页或筛选后分母变化，推荐由后端直接返回贡献率和集合总量。

### 12.2 单柜基线

建议单柜详情或独立对比响应补充：

- `baseline.type = "other_containers"`
- `baseline.container_count`
- `baseline.total` 与 `baseline.grades`
- `deltas.total` 与 `deltas.grades`
- `sample_status` 和不足原因

前端不得仅靠当前柜与 `/overview` 自行拼接模糊基线；否则“是否排除当前柜”和分母变化难以追踪。

## 13. 范围边界

### 13.1 首期包含

- 按日期范围对所有有效货柜进行销量、销售额、加权均价比较。
- 展示 A/B/C 等级结构及等级均价。
- 展示单柜总量贡献率和单柜等级贡献率。
- 支持排序、货柜搜索/筛选、仅看需关注（接口支持时）。
- 从全局对比进入单柜诊断，保持筛选和返回状态。
- 375px 移动端卡片化，无横向溢出。
- 明确空态、接口失败、零销量和样本不足。

### 13.2 首期不包含

- 多货柜自由勾选后生成独立对比工作台。
- 利润、成本、回款、应付结算排名。
- 机器学习预测、自动推荐售价。
- 销售地区、规格、客户、渠道维度比较。
- 用户自定义指标公式、列配置和异常阈值后台。

## 14. 验收标准

### 14.1 数据口径

- [ ] 对同一日期范围，货柜列表各柜销量之和等于全局总销量，各柜销售额之和等于全局总销售额。
- [ ] 任一货柜的整体加权均价等于该柜销售额除以该柜销量；销量为 0 时返回空值。
- [ ] 任一货柜 A/B/C 等级销量之和等于该柜总销量；等级结构占比加总允许四舍五入误差 ±0.1 个百分点。
- [ ] 所有 `grade_raw=BC` 的有效明细计入 C，界面统一显示“C 果（含 BC）”。
- [ ] 单柜销量贡献率和销售额贡献率分别使用全局同指标为分母，显示值与独立计算误差不超过 0.1 个百分点。
- [ ] 单柜诊断默认基线按最终确认规则计算；若采用推荐方案，基线必须排除当前柜。
- [ ] 等级结构差显示为百分点；均价差同时可验证绝对值与相对值。

### 14.2 排序与筛选

- [ ] 默认按销售额降序；切换销量、销售额、均价、贡献率及方向后顺序正确。
- [ ] 同值使用货柜 ID 稳定排序，空均价始终在末尾。
- [ ] 日期筛选同时作用于总量、等级、贡献率、基线、趋势和导出。
- [ ] 开始日期晚于结束日期时不发出无效分析请求，并显示可理解错误。
- [ ] 搜索/筛选货柜时，页面明确说明贡献率分母是否变化，行为与产品最终决策一致。

### 14.3 页面衔接

- [ ] 点击任一货柜进入正确单柜诊断，货柜 ID 与日期范围保持一致。
- [ ] 返回全局对比后恢复原筛选、排序和滚动位置。
- [ ] 横向列表、单柜摘要和导出中的同口径数字一致。
- [ ] 单柜基线标题显示日期、是否排除当前柜及基线货柜数量。
- [ ] 数据质量或经营异常可继续下钻到相关明细和源文件。

### 14.4 空态与样本

- [ ] 无数据、接口失败、零销量、单货柜、样本不足为五种可区分状态。
- [ ] 单货柜时不显示虚构基线；少于 3 个销售日期时不生成日销量异常结论。
- [ ] 样本不足时仍展示原始指标，但不使用“正常/优秀”等结论性颜色和文案。

### 14.5 手机端与可访问性

- [ ] 375px 宽度下无页面级横向滚动、文字遮挡、控件重叠或信息裁切。
- [ ] 货柜比较改为卡片，核心总指标无需展开即可看到，等级详情可展开。
- [ ] 所有点击目标不小于 44px，键盘焦点可见，排序和筛选均有标签。
- [ ] 正负差异不只依赖颜色，并显示方向、数值和单位。

## 15. 研发拆解建议

1. 先冻结贡献率、基线、搜索/筛选分母和单位四项产品口径。
2. 后端统一扩展货柜对比响应，补齐名称、周期、样本量、贡献率和基线元信息。
3. 前端完善类型与标准化逻辑，再改造货柜对比区域和单柜基线区域。
4. 增加后端计算测试、前端标准化/排序测试和 375px 浏览器验收。
5. 最后验证全局、单柜、导出三处数字一致，避免只验页面展示。

## 16. 待确认问题

以下问题会实质影响口径或交互，进入开发前需由产品经理/业务负责人明确：

1. **数量和均价单位**：`quantity` 是 kg、件、箱还是其他单位？页面是否固定显示“元/kg”？
2. **单柜基线**：是否接受推荐的“同期其他货柜（排除当前柜）”，还是必须使用“同期全部货柜（包含当前柜）”？
3. **货柜搜索的分母**：搜索仅缩小可见列表、贡献率仍按全部货柜，还是搜索后重算贡献率？推荐前者。
4. **货柜数量较多时是否分页**：如分页，贡献率必须由后端按全量比较集合计算，不能按当前页计算。
5. **是否首期展示销售额等级结构**：当前主结构按销量；销售额结构可作为展开指标，但不建议与销量结构共用同一条形图。
6. **样本不足阈值**：除现有“至少 2 个货柜、至少 3 个销售日期”外，是否需要最少明细数或最少销量阈值？
7. **异常筛选**：首期是否需要“仅看需关注”，以及数据质量提示与经营异常是否合并为一个状态？
8. **多柜并排**：业务是否存在必须同时固定 2–3 个货柜逐项比较的高频场景？若是，应单独进入二期多选工作台设计。
9. **默认日期范围**：全部历史、最近 7 天、最近 30 天，还是当前销售周期？推荐在有稳定“销售周期”定义前使用最近 30 天并允许清空。
10. **货柜完成状态**：是否有明确字段区分“销售中”和“已结柜”？当前模型没有稳定状态，不应仅凭结算摘要推断。
