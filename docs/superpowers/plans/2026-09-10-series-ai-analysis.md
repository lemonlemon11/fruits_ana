# 系列对比 · AI 分析结论（实施计划）

> 日期：2026-09-10 ｜ 状态：进行中 ｜ 作者：Codex

## 目标

在「系列对比」页增加「AI 分析结论」：用户点一次按钮，就能看到用大白话写成的
A/B/C 分级结论与建议，不需要自己读表。

## 边界

- 只做「系列对比」页；结算单对比页后续复用同一接口。
- 只使用当前勾选的结算单与到达日期范围，不引入新的数据源。
- 输出为纯文本结论（按固定小标题分段），不做问答式对话。
- 结论只依据后端算好的数字，提示词里明确要求不得编造、不得换算元/KG。

## 设计

1. 后端新增 `POST /api/analytics/series-comparison/analysis`：
   - 入参：`merchant_no[]`、`start_date`、`end_date`、`refresh`。
   - 复用 `get_series_comparison` 的聚合结果，转成精简数据包交给大模型。
   - 大模型配置读取仓库根 `.env` 的 `FRUIT_ANALYSIS_AI_API_KEY` / `FRUIT_ANALYSIS_AI_BASE_URL` /
     `FRUIT_ANALYSIS_AI_MODEL`；未配置时返回 503 与中文提示，不影响其它功能。
   - 调用方式：OpenAI 兼容 `POST {base_url}/chat/completions`，用标准库 `urllib`，
     **不新增第三方依赖**。
   - 结果按「功能 + 勾选 + 日期范围」哈希缓存到新表 `ai_analysis`，`refresh=true` 时重新生成。
2. 前端「系列对比」页新增 `SeriesAiAnalysis.vue` 卡片：
   - 未生成：显示说明与「生成 AI 分析」按钮（勾选不足两个时按钮禁用）。
   - 生成中：显示「正在生成，请稍候」。
   - 已生成：按小节展示结论 + 模型名与生成时间，并提供「重新生成」。
   - 失败：显示中文错误提示与「重试」，不影响页面其它内容。
3. 文案要求：面向果农，避免「加权均价 / 贡献度」等术语，沿用「平均每件售价」说法。

## 风险

- 大模型响应可能较慢（数十秒），前端需要明确的加载态；后端超时设为 120 秒。
- 大模型可能输出错数字：提示词要求「只引用给定数字」，且页面同时展示原始表格便于核对。
- API Key 只从 `.env` 读取，禁止写入代码或提交。

## 验证

- 后端：`pytest` 覆盖提示词构建、缓存命中、未配置 503、上游失败 502（用 monkeypatch 假造调用）。
- 前端：`npm run test` 覆盖结论文案归一化与文案守卫，`typecheck` + `build` 通过。
- 真实调用：配置就绪后用真实结算单验证一次（需要重启后端服务才会加载新接口）。
