# 水果等级销售分析平台：产品经理沟通主持方案

日期：2026-09-09  
状态：待召开产品评审会  
主持人：项目负责人（负责控时、收敛决策和会后同步）

## 1. 沟通目标

本次会议面向产品经理、业务负责人和研发/设计代表，目标是把已确认的经营分析需求转化为可验收的页面与数据行为，并为后续详情表格接入提前建立边界。

会议结束时应完成以下结果：

- 确认管理者首页的紧凑信息架构，以及“全局汇总 / 单柜诊断”两种视图的入口和切换方式。
- 确认折线图、等级饼图和数据对比区的展示对象、时间口径、交互与空数据规则。
- 确认“销售进行中每日跟踪”和“销售结束后复盘”两类场景的默认筛选与重点指标。
- 形成带负责人和截止时间的行动项；未决事项进入产品待确认清单，不在会议中隐式假设。

## 2. 已确认的产品基线

以下事项已由业务方确认，本次会议只做澄清和落地细化，不重新争论范围：

| 主题 | 已确认结论 |
| --- | --- |
| 使用者 | 管理者 / 老板，关注经营结果和等级销售表现 |
| 首期重点 | 不以回款口径为核心，优先看不同等级水果的销售情况 |
| 等级范围 | A、B、C；原始 `BC` 统一归入 C，界面显示“C 果（含 BC）” |
| 视图 | 全局汇总与单柜诊断两种视图并列，可按场景切换 |
| 场景 | 销售过程中按日跟踪；销售结束后进行单柜复盘，两种场景都需要 |
| 核心指标 | 销售数量、销售金额、加权均价、数量占比 |
| 筛选 | 日期范围、货柜；后续预留品种/销售地区等维度 |
| 数据可信 | 汇总可下钻至标准化销售明细，并追溯到批次和原始文件 |
| 辅助信息 | 售后、费用、清关税费、结算金额用于解释单柜结果，不作为首页核心排序 |
| 后续输入 | 未来会提供一份更细的详情表格；本期只预留待办，不提前绑定字段 |

## 3. 本轮页面改版提案

### 3.1 紧凑布局

- 顶部固定“场景切换 + 日期范围 + 货柜筛选 + 导出”操作条，减少页面上下跳动。
- 第一屏采用“核心指标条 + 等级摘要”布局，A/B/C 三组指标在同一行或两行内完成对比。
- 第二屏左右并列放置“日趋势折线图”和“等级结构饼图”，图表标题直接写明指标和口径。
- 第三屏展示“货柜/等级对比”表格或条形对比，保留异常标记和下钻入口。
- 低频的导入批次、数据质量、售后费用等信息放入可展开区域，避免挤占经营指标空间。
- 桌面端优先信息密度，窄屏自动改为单列；不允许出现横向滚动、文字遮挡或控件重叠。

### 3.2 折线图

默认展示筛选范围内按销售日期聚合的趋势，建议提供“销量 / 销售额 / 加权均价”切换。横轴为销售日期，纵轴单位随指标变化；悬浮提示同时显示当天值和筛选条件。

当只有一个日期或没有有效明细时，显示明确的单点/空数据状态，不绘制误导性的平滑曲线。日期排序按自然时间升序，缺失日期不补 0，除非产品经理确认要按营业日补齐。

### 3.3 等级饼图

饼图默认按销量展示 A/B/C 结构，中心或标题注明“数量占比”。每个扇区必须显示等级、数量和百分比；C 的图例写为“C 果（含 BC）”。销量为 0 时展示空状态，不显示 100% 的伪占比。

建议保留“按销售额查看”切换，但如果首期不做，需在会议纪要中明确列为二期，避免用户将销量饼图误认为金额结构。

### 3.4 数据对比区

“数据对边”暂按“数据对比”理解，建议提供两层对比：

1. **货柜横向对比**：按货柜列出 A/B/C 数量、数量占比、加权均价，突出最高/最低和异常偏离。
2. **单柜基线对比**：在单柜诊断中，将当前货柜与全局同期（相同日期范围、排除当前柜或按产品确认）进行对照，展示绝对值与差值。

差值必须带方向和单位，例如“均价 -2.4 元/kg”“C 果占比 +6.8 个百分点”，不得只显示无单位的百分比。对比基线不可因筛选条件变化而悄悄改变，应在标题或提示中说明。

- “这个问题先判断是否影响首期验收；不影响的记录为二期，不在现场扩 scope。”

## 5. 需要产品经理确认的问题清单

### A. 场景与默认状态

1. 首页默认进入“每日跟踪”还是“销售复盘”？是否记住上次选择？
2. 每日跟踪默认日期范围是最近 7 天、当前销售周期，还是最近一次导入批次？
3. 复盘场景是否默认选中最近完成的货柜？“完成”由人工标记还是按结算摘要推断？
4. 两种视图是同页并列，还是使用顶部 Tab 切换后保留筛选状态？

### B. 折线图

1. 首期默认曲线显示销量、销售额还是加权均价？是否需要同图双轴？
2. 是否允许按 A/B/C 拆分为三条线，还是仅展示总量并通过等级摘要查看结构？
3. 缺失销售日期是否断线、补零，还是显示“无数据”标记？
4. 金额单位、数量单位、均价单位分别采用什么显示精度和币种？
5. tooltip 是否需要同时显示当天 A/B/C 明细、当日占比和来源批次？

### C. 饼图

1. 饼图只按销量，还是提供销量/销售额切换？
2. 是否显示标签线、中心总量和环形图样式？小于 3% 的扇区如何避免标签重叠？
3. C（含 BC）是否需要在 tooltip 中额外展示 BC 原始数量？
4. 点击扇区后是否联动页面筛选、对比表和明细列表？

### D. 数据对比

1. “全局同期”基线是包含当前柜的全局，还是排除当前柜的其他货柜？
2. 横向对比默认按销量、销售额、均价还是异常优先排序？
3. 差值使用绝对差、相对差，还是两者都显示？百分点与百分比如何区分？
4. 异常阈值由产品配置、后端配置还是固定在首期？谁负责确认阈值？
5. 对比表是否支持导出当前排序、筛选和列配置？

### E. 数据与验收

1. 未来详情表格的预计提供时间、文件格式和主键是否已有负责人？
2. 详情表格中的规格、品质状态、销售地区是否会成为首期验收维度？
3. 指标争议以标准化销售明细为准，还是允许结算摘要覆盖？
4. 页面中的“暂无数据”“数据质量异常”“接口失败”是否需要不同文案和处理动作？

## 6. 图表与对比验收标准

### 通用

- 所有图表使用当前筛选条件，切换日期或货柜后在可接受时间内刷新，且标题显示筛选范围。
- 无有效数据时显示空状态和原因，不显示 0%/100% 等误导值；加载和接口失败状态可区分。
- 桌面宽屏和 375px 窄屏均无横向溢出；图例、单位、tooltip 不被裁切。
- A/B/C 顺序稳定，C 明确标注“含 BC”；颜色在所有图表和表格中保持一致。

### 折线图

- 日期按升序，数据点与 `/api/analytics/trend` 返回值一致。
- 每个点可读出日期、指标名称、数值和单位；数量、金额、均价切换不改变日期筛选。
- 单点、空数据和缺失日期行为符合产品确认的规则，并有自动化测试覆盖。

### 饼图

- A/B/C 扇区数量之和等于当前筛选范围总数量；百分比加总允许四舍五入误差 ±0.1 个百分点。
- C 扇区包含所有 `grade_raw=BC` 的记录，原始等级仍可在明细追溯。
- 扇区点击（若确认实现）能联动等级筛选，并可恢复到“全部等级”。

### 数据对比

- 横向对比和单柜基线使用同一指标服务和同一筛选口径，不出现页面间数字不一致。
- 每个差值带方向、单位和比较对象；数量占比差值使用“百分点”文案。
- 对比基线、排序和异常阈值在页面或 tooltip 中可解释，导出结果与页面一致。
- 点击货柜或等级可进入对应单柜诊断/明细，来源 ID 可追溯到批次和原始文件。

## 8. 风险与应对

| 风险 | 触发信号 | 应对方式 | 责任人 |
| --- | --- | --- | --- |
| 图表需求膨胀 | 讨论扩展到利润、成本或外部行情 | 回到已确认指标；新增内容进入二期候选 | 主持人/产品经理 |
| 对比基线含义不一致 | 业务、产品、研发给出不同“同期”解释 | 现场写出分子/分母和示例数据，形成决策记录 | 产品经理/数据负责人 |
| 数据量不足以支撑结论 | 某日或某等级仅有少量明细 | 显示样本量/数据质量提示，不做强结论 | 数据负责人 |
| BC 映射被误解 | 页面只显示 C，用户要求拆回 BC | 保留 grade_raw，首期界面统一 C；拆分列为后续需求 | 产品经理 |
| 详情表格延迟 | 文件格式、主键或提供时间不明确 | 先完成当前结算单链路，建立详情表格待办和接入验收清单 | 业务负责人 |
| 紧凑布局降低可读性 | 375px 或宽屏出现拥挤、标签重叠 | 以最小字号、最小控件尺寸和断点验收为准 | 设计/前端 |

## 10. 后续详情表格待办（本期不实现）

收到详情表格后，单独召开数据接入评审，至少完成：

1. 确认文件格式、工作表、表头位置、编码和更新频率。
2. 识别稳定主键，以及与货柜号、销售日期、销售明细的关联键。
3. 建立字段映射：规格、品质状态、销售地区、客户/渠道等；明确哪些进入首期看板、哪些只保留追溯。
4. 评估与现有结算单的重复记录、金额差异和冲销规则，避免重复计算。
5. 为新增维度补充导入错误、BC 映射、空值和重复数据测试。
6. 更新 API 契约、指标口径、对比基线和导出字段，并重新执行 UAT。
