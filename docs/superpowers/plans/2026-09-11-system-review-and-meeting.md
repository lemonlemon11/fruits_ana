## 3. 六个专项诊断

### 3.1 数据层：入库字段被过度压缩

- `backend/app/services/settlement_detail_service.py:12` 的 `SETTLEMENT_FIELDS`
  只暴露 `after_sale_amount` / `fee_amount` / `customs_tax` / `payable_amount`，
  **`sales_amount` 与 `goods_amount` 已入库但前端拿不到**。
- `fee_detail` 以整串文本存储（`backend/app/models.py`），费用结构无法按类别聚合或对比。
- `grade_raw` 已保留原始等级，但分析链路只用 `grade`（A/B/C）。

### 3.2 指标层：口径正确但洞察深度不足

- 均价是单一加权值，掩盖 A5/A6、熟/裂之间的真实价差（实测 A6 均价约 558 元/件，
  `A5熟` 仅 430 元/件，差 128 元/件）。
- `backend/app/services/analytics_core.py:24` 的 `AnomalyThresholds` 为硬编码固定比例，
  且「同期基线」仅在同一筛选范围内比较，样本少时易误报。

### 3.3 AI 层：结论只覆盖「卖得怎么样」

- `backend/app/services/ai_analysis_service.py:86` 起构造的 payload 只含销售聚合
  （件数、金额、均价、占比、价差），**未喂费用、清关、应付数据**。
- 因此 AI 永远说不出「这单到手多少、被费用吃掉多少」，与业务方关心的经营结果脱节。

### 3.4 导入层：唯一键可靠，但字符串未规范化

- `backend/app/services/import_service.py:189` 以商号做唯一键、覆盖时同一事务替换，语义正确。
- 但商号字符串未归一化，`单637` 与 `640` 会被当成两套命名体系，下拉排序与系列识别均受影响。
- 清关费为空是正常业务（以清关单为准），但金额字段的**异常值**（负数、与摘要不符）
  当前不产生 `data_issue`，问题会被静默带过。

### 3.5 前端层：能看懂，但还不能决策

- 术语仍为「加权均价」等专业口径，与「果农版简化」目标（`docs/TODO.md` P1）不一致。
- 手写 SVG 图表（ADR-007）普遍缺单位、缺对比基准线、缺「异常高亮」。
- 导出/截图分享路径薄弱，只有总览 CSV 与结算单 xlsx。

### 3.6 运维层：无 CI，验证依赖本机

- 无 CI、无容器化（已由 ADR 记录为暂不引入）；交接依赖人工维护
  `docs/HANDOFF.md`，多模型协作时容易状态漂移。

## 4. 优化方案（按优先级）

### P0（下一步主线，零新增数据依赖）

- **等级细分落库/落服务**：从 `grade_raw` 解析出 A5/A6、B5/B6/B7、BC/C 号，
  产出细分价格阶梯表。实测信息量最大、收益最高。
- **商号规范化 + 数据质量兜底**：归一化商号（去「单」前缀、统一数字格式）；
  对「应付为负 / 明细与摘要金额不符 / 必填金额缺失」自动生成 `data_issue`
  （清关费为空属正常，不做告警）。
  涉及 `backend/app/parser/settlement_parser.py`、`backend/app/services/import_service.py`。
- **清关费口径已确认**：以清关单数据为准，清关单没有即为没有清关费；单 640 的应付
  384,740 元为真实值，不视为数据错误（见 ADR-012）。
- **等级细分（下一阶段主线，已确认）**：从 `grade_raw` 解析号别与品质后缀，
  产出 A5/A6、B5/B6/B7、BC/C 号的价格阶梯（见 ADR-013 与实施计划）。

### P1

- **元/KG 口径**：从 `spec_raw` 解析箱重（17/19/19.5KG），新增每公斤售价，
  消除箱重差异后做真实价格对比（改动集中在 `backend/app/services/series_analytics_service.py`）。
- **单位经营结果 + 费用结构**：把 `fee_detail` 结构化（代卖佣金 / 车位费 / 运费 / 入场费 /
  搬运费 / 打冷费），输出每件应付、费用率、清关占比。
- **AI 结论升级**：payload 加入应付、费用率、清关与最低价等级，让结论从「行情」推进到「这单到手多少、问题在哪」。

### P2

- 术语白话化与图表增强（单位、对比基准、截图分享）。
- 成本数据接入后的利润测算（ADR-003）。
- 销售地区维度回填（`sales_region` 已预留）。

## 5. 数据挖掘地图

### 5.1 零新增数据即可挖掘

| 机会 | 依赖字段 | 说明 |
| --- | --- | --- |
| 等级细分价格阶梯 | `grade_raw` | A5 vs A6、B5/B6/B7、BC/C 号对比 |
| 品质因子分析 | `grade_raw`（熟 / 裂） | 裂果率、熟果占比 → 折价与损耗 |
| 元/KG 真实价格 | `spec_raw` | 消除箱重差异后的可比价格 |
| 单件经营结果 | `settlement_summary` | 每件应付、费用率、清关占比 |
| 费用结构拆解 | `fee_detail` | 六类费用占比与单柜横向对比 |
| 单柜复用识别 | `container_no` | 同一柜号多结算单的业绩合并 |
| 对账一致性看板 | `sale_record` + `settlement_summary` | 自动核对明细金额与摘要 |
| 数据质量看板 | `data_issue` + 空值率 | 缺失字段与异常金额预警 |

### 5.2 需先规整数据

- 到港日期 vs 销售日期 → 真实销售周期。
- 客户 / 买家维度（解析器已支持 `customer`，但源文件当前无此列）。
- 销售地区（`sales_region` 全空）。
- 系列编号规范（`宝贝01` vs `宝贝L004`）。

### 5.3 需新增数据

- 采购成本 → 毛利 / 利润（当前 Blocked，见 ADR-003）。
- 库存与冷藏损耗数据。
- 价格弹性与量价关系、售完时间预测（需更长历史）。
