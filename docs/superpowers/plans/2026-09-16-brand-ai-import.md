# 品牌结算单「大模型解析 + 二次确认入库」

> 2026-09-16 · 状态：待评审后开工 · 相关：ADR-026

## 背景与目标

各品牌（香香 / 宝贝 / 晴牌 …）导出的结算单版式不统一，现有固定模板解析吃不下来。
改用「每个品牌一份提示词配置 + 大模型解析」把文件解析成录单草稿，先回填到「录单」同款界面
人工二次确认，确认后才写入系统。

## 范围

- 本期品牌：`香香`、`宝贝`、`晴牌`；`润控金象` 不做。
- 入口：导入入口**先选品牌**（客户口径叫「品种」），再选文件；只走所选品牌的解析配置。
- 不做：模型微调；不做免确认自动入库；不改分析口径与既有指标。

## 客户已确认的口径

1. 解析能力＝**每品牌一份配置**（结构映射 + 提示词 + 校验规则 + 样例回归集），不是微调模型。
2. 导入入口的「品种」＝**品牌**，上传时**人工选**；品牌混放文件（如香香目录里的宝贝单）靠人工选兜住。
3. 等级拆分：字母 → 品种；数字/区间 → 规格（头数）；`熟/裂/尾` 等后缀 → 备注。
   归一：`B6/7熟` → B，`C8/9大裂` → C（`BC` 仍按现口径归 C）。
4. **规格（头数）改文本**，原样存 `6/7`（`sale_record.piece_count` 由 INTEGER 改 VARCHAR）。
5. 标红项：**人工修改完再保存**。
6. 解析服务/模型不可用：明确提示不可用，**不进入录单**。
7. `tickets/` 下的客户文件允许入库做回归样例。

## 规格字段存储与「进分析指标」方案

需求：规格（KG）原样存 `9/10`，但这一列要参与分析指标。方案是**原文 + 派生数值列**：

- `sale_record.spec_kg`（VARCHAR(32)）：保存**归一后的规范值**（`9/10`、`10`），负责展示、回显、导出；
  逐字原文留在 `spec_raw`，写法变体（`9-10`、`9~10`、全角、带单位）统一收敛成 `min/max` 形状。
  完整规则表见设计文档 3.1 节。
- `sale_record.spec_kg_min` / `spec_kg_max`（NUMERIC(18,2) NULL）：写入时由统一入口
  `parse_range()` 从原文解析出的区间端点，负责聚合分析与建索引。
- `sale_record.piece_count` 同样处理，配 `piece_count_min` / `piece_count_max`。
- 单值 `10` 解析为 `10/10`；`9/10`、`9-10`、`9~10` 均解析为 `9/10`；解析失败留空并标红
  （解析不出来的规格无法进统计，必须在二次确认页修正）。

为什么不只存一个数值：区间被抹平后口径无法回溯；保留 min/max 后，想改「取上限 / 取中点 /
取下限」不用回补历史数据。

分析口径：**维度**用原文归一后的标签分桶（`10KG` 与 `9-10KG` 是两个桶，不合并）；
**数值聚合**（平均规格 KG 等）需要区间代表值，默认取**上限**（`9/10` → 10），
该口径须写入 DECISIONS 后才实现。

## 字段映射规则

| 文件写法 | 品种 | 规格（头数） | 规格（KG） | 备注 |
| --- | --- | --- | --- | --- |
| `B3（9KG）` | B | 3 | 9 | |
| `A3/4（10KG）` | A | 3/4 | 10 | |
| `B6/7熟` | B | 6/7 | — | 熟 |
| `C8/9大裂` | C | 8/9 | — | 大裂 |
| `A3（9/10KG)尾` | A | 3 | 9/10 | 尾 |
| `损/少果`、`验果抽检`、`夹肉/溶` | — | — | — | 非销售行 |

- 非销售行不计入销售金额，按行归类到售后/损耗区，保留原文与数量。
- 全角/半角括号、`KG/公斤` 大小写统一归一。

## 架构

- `backend/app/parser/brand_profiles/`：香香 / 宝贝 / 晴牌 各一份声明式配置
  （表头映射、明细区识别、等级拆分正则、售后/费用/清关区识别、合计校验）。
- **大模型解析**：整表文本化 + 品牌提示词 → 模型输出槽位 JSON；归一化、算数、判定由代码完成，
  模型输出必须通过归一器与校验器才能进草稿。
- `POST /api/imports/preview`：品牌 + 文件 → 「录单草稿 + 问题清单」，**不落库**。
- 人工确认后调用现有 `POST /api/entry` 落库（商号唯一键、覆盖逻辑、权限不变）。

## 校验与标红

逐行、逐字段定位（行号 + 字段名），命中即标红并给出原因：

- 必填缺失（销售日期 / 品种 / 头数 / KG / 数量 / 单价）
- 金额 ≠ 数量 × 单价
- 明细合计 ≠ 文件「销售金额」
- 售后合计 / 费用合计 / 应付贵方总金额对不上
- 等级无法归一（既不是 A/B/C，也无法按规则拆出字母）
- 日期无法解析

## 风险

- `piece_count` / `spec_kg` 改类型需要 `ALTER TABLE`，线上库要单独确认执行窗口；
  两者都不参与任何分析指标，改动不影响既有看板口径。
- 规格（KG）也可能出现区间（`9/10KG`，见 `tickets/香香/629结算单（香香L001）(1).xlsx` 第 40 行），
  该列处理方式待确认（见下）。
- 大模型输出不稳定：必须过校验，且解析结果全程可人工修改。
