# 结算单选择器交互改造（2026-09-11）

## 背景

「系列对比」页原来是**把当前日期范围内的全部结算单平铺成勾选卡片**。当前只有 4 张单时可用，
但业务预期结算单会持续增长，平铺会带来三个问题：

1. 单量上百后页面被选择区占满，找不到目标单；
2. 每勾一下立即请求一次对比接口，多选时产生多次无谓请求；
3. 已选项只以「已选 N / 6」一句文字体现，看不出具体是哪几张。

## 备选方案

| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A 就地折叠 + 搜索 | 保留在页面内，系列默认折叠，加搜索框与已选条 | 改动最小，不新增交互层 | 单量很大时仍要滚动，主页面仍被选择区占据 |
| B 抽屉式选择器（采用） | 主页面只留「已选 chips + 选择按钮」，搜索 / 折叠 / 勾选都在抽屉里 | 主页面永远干净；搜索只作用在抽屉内；草稿确认只发一次请求；单量上千也可用 | 多一个弹层，需要处理 Esc、滚动锁定与移动端全屏 |
| C 表格式选择 | 结算单做成可排序、分页的表格 | 信息密度高，方便核对数字 | 果农向界面偏报表，移动端体验差 |

## 采用方案（B）的交互规则

- 主页面：`已选 N / 6` + 已选 chips（含商号与单号，可单个 ×移除）+ 「选择结算单」+「清空」。
- 抽屉内：
  - 搜索框按商号、单号、系列、柜号匹配；搜索时系列自动展开并显示命中数量；
  - 系列默认展开、可逐组收起；每组有「全选本系列 / 取消本系列」；
  - 勾选写入**草稿**，页头实时显示 `已选 N / 6`；选满后未选项置灰并提示「先取消一张再选」；
  - 底部「取消」丢弃草稿，「确定（N 张）」才把选择交回页面并刷新对比结果。
- 键盘与可访问性：`role="dialog"` + `aria-modal`，打开后焦点落在搜索框，Esc 关闭，
  打开期间锁定页面滚动；组头按钮用 `aria-expanded` 表达折叠状态。
- 移动端：抽屉整屏宽度，选项改为单列。

## 实现位置

- `frontend/src/utils/settlementPicker.ts`：搜索过滤、草稿勾选、整组追加与整组选中判断（纯函数，可单独测试）。
- `frontend/src/components/SettlementPicker.vue`：触发器 + 抽屉。
- `frontend/src/views/SeriesComparisonView.vue`：只保留 `selected` 与 `applySelection`，移除平铺列表与逐次请求的旧逻辑。

## 验证

- 单元测试：`frontend/tests/settlement-picker.test.ts`（过滤、上限保护、整组追加与整组选中）。
- 守卫测试：`frontend/tests/farmer-ui-copy.test.mjs` 断言选择器已收进抽屉、且主页面不再平铺。
- 浏览器实测（53001 dev-preview，桌面 1440px / 移动 390px）：主页面平铺选项数 0；
  搜索「637」命中 1 张；「取消」不改已选；勾选后草稿显示 `已选 2 / 6`；
  「确定」后 chips 同步；系列收起后可见选项 0、展开后 4；全选本系列后 `已选 4 / 6`；
  无横向溢出、无控制台报错。
