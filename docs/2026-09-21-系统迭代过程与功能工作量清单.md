## 一、项目概述

### 1.1 系统定位

SLD-水果市场销售分析系统面向果农，围绕水果销售的 A/B/C 三级统计口径，提供从数据导入到经营分析的一体化能力。核心业务链路为：

```text
数据导入 → 二次确认/手工录单 → 销售看板 → 单柜诊断 → 货柜/系列对比 → 导出与 AI 问答
```

系统重点解决三个问题：

1. 结算单格式不统一，需要兼容多文件、多版式导入。
2. 等级、单号、商号等口径在历史数据中写法不一致，需要统一展示与统计规则。
3. 果农需要一眼看懂卖得怎么样，要求桌面端与手机端都清晰易用。

### 1.2 技术架构

| 层级 | 技术方案 |
| --- | --- |
| 用户端前端 | Vue 3 + Vue Router + Vite，无状态管理库、无 UI 组件库 |
| 图表 | 手写 SVG 图表组件 |
| 后端 | FastAPI + SQLAlchemy 2.0 + Uvicorn |
| 数据库 | MySQL，PyMySQL 驱动 |
| AI 能力 | 大模型 function calling，完成自然语言数据问答与分析结论生成 |
| 部署 | 本地同机部署，Nginx 托管前端并代理 `/api` 到后端 |
| 管理端协同 | 与 `fruits_ana_admin` 管理端共用角色、权限、菜单、通知与字段转换规则 |

## 二、系统迭代过程

### 2.1 总体节奏

系统从 2026-09-08 开始进入工程化建设，到 2026-09-21 已进入上线前收口阶段。开发过程不是一次性堆功能，而是按“先搭数据底盘，再做分析页面，再补录入闭环，最后做上线前体验与质量收口”的顺序推进。

### 2.2 分阶段迭代

| 阶段 | 时间 | 主要工作 | 阶段成果 |
| --- | --- | --- | --- |
| 1. 需求与设计 | 09-08 | 明确业务目标、数据口径、页面结构和实施计划 | 平台设计、实施计划、初始数据模型 |
| 2. 核心分析原型 | 09-08 至 09-09 | 完成销售数据模型、文件导入、总览看板、等级统计与基础图表 | 可运行的销售分析原型 |
| 3. 单柜与货柜对比 | 09-09 至 09-10 | 重构单柜诊断、货柜对比、主题换肤和移动端适配 | 果农可直接查看单柜与货柜经营情况 |
| 4. 商号维度与系列对比 | 09-10 | 将结算单唯一键从柜号调整为商号，新增系列对比与 AI 分析 | 多结算单按系列横向比较，支持 AI 结论 |
| 5. 等级细分与体验完善 | 09-11 至 09-14 | 增加等级细分、页签外壳、图表图例提示、单号/商号双写、Nginx 部署 | 用户端工作台和移动端体验明显提升 |
| 6. 录入链路重构 | 09-15 至 09-18 | 新模板多文件导入、二次确认、手工录单、顺仔 AI 问答、上线前清理 | 导入与录单形成完整闭环 |
| 7. 上线前收口 | 09-18 至 09-21 | 专业测试团队回归、移动端改版、权限模型收口、文案口径统一、真实浏览器验收 | 当前处于上线前质量收口阶段 |

### 2.3 迭代特征

- **先口径后页面**：等级映射、销售金额/销量/均价、商号唯一键等基础规则先确定，再扩展页面，避免后期返工。
- **先桌面后移动**：桌面功能稳定后，统一补齐移动端布局和交互。
- **先功能后质量**：主链路完成后，集中投入测试修复、权限收口、文案统一和真实环境回归。
- **保留原始数据**：等级原文、原始单号、原始商号都保留在库，展示层使用统一适配值，可追溯、可回退。

### 4.3 工作量特征

- 高复杂度集中在“文件导入与二次确认”和“对比与诊断分析”，因为真实结算单格式不规则，且分析维度需要统一口径。

- 测试与修复不是一次完成，而是在专业测试团队回归、真实浏览器验收和多会话并行修改后持续收口。
